> 供 AI 后端 / 研发对照使用。与各菜单 `20260902V*` PRD 第 12–14 章配套。  
> 规格真源：可见 UI + PRD「已明确」条款；「演示规则」「未确认」禁止当成已确认校政。

## 1. 三套「生效 / 确认」状态（禁止混用）

| 域 | 逻辑字段 | UI 常见文案 | 枚举（代码） | 所属菜单 |
|----|----------|-------------|--------------|----------|
| 计划生效 | `submitStatus` | 生效状态 | `draft` / `submitted` / `reverted` | 开课计划 |
| 安排生效 | `taskSubmitStatus` | 生效状态 | `draft` / `submitted` / `reverted` / `cancelled` | 开课安排；停课见课程班 |
| 班级授课确认聚合 | `teachingConfirmStatus` | 授课确认 | pending / partial / confirmed 等（以原型展示为准） | 开课安排列表 |
| 教师确认包 | Confirmation Package Status | 确认状态 | `not_sent` / `pending` / `disagreed` / `confirmed` / `admin_proxy` | 授课确认管理 / 教师端 |

**禁止**：把计划生效、安排生效、确认包状态建成同一个 `status` 字段。

## 2. 关键因果链

```
开课计划 draft → submitted
        ↓
开课安排 Course Setting → 师资安排 → taskSubmitStatus=submitted
        ↓
授课确认发送 → 教师 confirmed / admin_proxy（齐套）
        ↓
排课计划入列（BR：齐套 + 安排已生效；共同授课关联班均齐套）
```

**替换打断**：授课教师替换后若未齐套 → `taskSubmitStatus` 打回 `draft`，需重新确认（`授课教师替换` BR001，已明确对照原型）。
