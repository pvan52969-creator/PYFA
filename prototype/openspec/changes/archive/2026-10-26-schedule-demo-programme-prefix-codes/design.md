# Design

## Context

See proposal.md - Why。真实课号参考：用户提供的《课程班-202609-…xlsx》（字段含课程代码 / 课程名称 / 课程班名称）；前缀统计与 `PROGRAMME_CATALOG` 专业代码高度一致。当前排课假前缀种子集中在 `app.js`：`CDF201/202/203`（mec 学生闭环）、`CDX101/102`（跨批教师）、`CTS101`、`RM*` / `RCL*` 等。Excel 中已有 `MEC201` 等真号，故演示号段用 **9xx** 避撞。

## Goals / Non-Goals

**Goals:**

- 排课用户可见演示课号：`{PROGRAMME.code}{9xx}`，前缀随 `programmeKey`
- 全量替换假前缀字面量与闭环文档/注释，保持冲突可追溯
- 课名/课组不强制改

**Non-Goals:**

- 不把整张 Excel 导入为运行时库
- 不改冲突算法、排课交互、开课正式目录课号
- 不强制 GE（`G####`）/ MPU 演示课改为三字母专业前缀（若触及，单独用现有 MPU/GE 规则）

## Decisions

### 1. 命名映射表（建议默认）

| 旧课号 | 所属/用途 | 新课号（示例） |
|--------|-----------|----------------|
| CDF201 | mec 学生锚点已排 | MEC901 |
| CDF203 | mec 学生探测 | MEC903 |
| CDF202 | mec 教师探测 | MEC902 |
| CDX101 | 跨批教师锚点 | 按同伴 `programmeKey` → 如 FIN901 / 原批次专业 9xx |
| CDX102 | 跨批教师查询同伴 | 同上另一专业或同专业 MEC904 等 |
| CTS101 | 冲突查询样例 | 改为复用闭环锚点课号或 `MEC905` |
| RM* / RCL* | 教室演示 | 按所挂专业改 `XXX9xx`，或教室专用仍挂某演示专业前缀 |

实现前在 tasks 中先落一张「旧→新」对照表再改代码，避免漏改。

### 2. 避撞校验

对照 Excel 课程代码集合（可脚本一次性生成 `Set`，不必进仓库二进制）：断言所有新演示号 ∉ 真课集合。号段默认 901–919；若不够再扩 9xx。

### 3. catalogId / gdemo 挂靠

现有 `gdemo-${code.toLowerCase()}` 随 code 变更即可；`gdemo-cross-*` 同步。无需改开课正式 catalog。

### 4. 课名策略

保持现有英文课名（如 Marine Environmental Chemistry）即可；不必从 Excel 抄名。课程组短名维持 A组/Group 规则。

### 5. 范围边界

- **改**：排课模块种子与可见引用
- **不改**：开课管理里已是真规格的 `ACC312` 等目录课；排教室菜单逻辑

## Risks / Trade-offs

- [漏改硬编码导致闭环断裂] → 全库搜旧课号；改完跑学生/教师冲突口头路径
- [CDX 跨批专业选错导致叠学生冲突] → 保持「跨批」设计：同伴挂非 mec 批次专业前缀
- [9xx 日后与真课扩展撞号] → 文档约定演示号段；验收脚本可再跑一次 Excel diff

## Migration Plan

纯演示数据替换；无持久化迁移。刷新原型即见新课号。回滚：恢复旧字面量映射表。
