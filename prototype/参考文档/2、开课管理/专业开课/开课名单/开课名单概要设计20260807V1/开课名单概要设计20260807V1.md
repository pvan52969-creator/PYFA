## 2. 建设目标与范围

### 2.1 目标

在**任务安排已生效**后，按开课任务（教学班）维护各小组学生名单，支持不开放选课的手工维护与开放选课边界说明，以及批量退回至开课安排。

### 2.2 范围内

- 按开课任务列表展示（可见条件：计划已生效 **且** 任务已生效）
- 「管理名单」进入分组工作台「学生名单」Tab：预置名单、添加、调组、移除、一键分配、保存
- 列表「人数」入口查看学生名单概览
- 批量「退回」至开课安排（任务回草稿，**名单可保留**）
- 操作记录

### 2.3 非目标（不在本菜单）

- **无独立「提交名单」按钮**——进入名单维护本身以任务已生效为前提，不存在跳过安排生效的提交动作
- 不含计划生成与任务三步安排本体
- 不含通识 / 特殊开课名单（设计中）
- 不含学籍异动主数据维护

## 3. 用户角色与使用场景

| 角色 | 场景 | 目标 |
|------|------|------|
| 教务 | 任务生效后 | 将学生分配到各小组 |
| 教务 | 不开放选课老生班 | 从预置名单分配或一键分配 |
| 教务 | 需改安排但未清名单 | 退回至开课安排后继续维护 |
| 学院 | 分组环节 | 设置小组人数上限与需求说明 |
| 选课应用 | 开放选课课程 | 生成默认名单（开课侧仍可手动调整，边界待确认） |

## 4. 在整体业务链路中的位置

```text
开课计划 → 开课安排（授课确认齐套 → 任务生效）→ 【开课名单】→ 排课 / 考勤等
                              ↑
                    退回（名单可保留）
```

操作流程图：专业开课路径为「计划 → 安排 → 授课确认 → 名单」；未完成授课确认不可进入名单阶段。本页处于专业开课末端，消费分组结构与容量，产出稳定名单供下游。

## 5. 主业务流程

1. **前置**：开课安排中任务已生效（隐含计划已生效、授课确认已齐套）。
2. 管理员按学期/学院/专业/单位/课号筛选任务列表。
3. 点击「管理名单」进入工作台，按小组维护学生：预置名单分配、添加学生、调整分组、移除、一键分配。
4. 保存名单；实际人数不超过小组上限，不改变计划人数/名额上限（老生场景）。
5. 若需修改分组/教师等安排侧信息，列表勾选后「退回」至开课安排（填退回说明）；已维护名单保留。
6. 开放选课课程默认名单由选课应用生成；页内提示不作为主维护入口（仍保留管理名单能力）。

**与安排页「撤回」区别：** 安排撤回会重置学生小组分配；名单页退回安排可保留名单。

## 6. 职责边界

| 职责 | 说明 |
|------|------|
| 负责 | 任务生效后的学生入组、调组、移除、一键分配、退回至安排 |
| 不负责 | 计划/任务安排、授课确认、分组结构定义（在上游完成） |
| 与他模块交接点 | 任务已生效 ← 开课安排；分组容量/预置名单 ← 计划与安排；稳定名单 → 排课/考勤 |
