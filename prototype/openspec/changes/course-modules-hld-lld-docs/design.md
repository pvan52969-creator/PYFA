## Context

- 见 `proposal.md` 动机与范围。
- 已知：目标菜单对应原型页面已存在；操作流程图已对齐侧栏（计划 → 安排 → 授课确认 → 名单）；`参考文档/2、开课管理/` 下已有按二级菜单拆分的需求文档目录。
- 约束：设计文档以中文为主，尽量不用英文；禁止编造未确认的学校政策、接口字段与数据来源；未知写「待确认」。
- 本变更为文档交付，不改原型行为。
- **范围已确认**：每个二级菜单单独建文件夹，各出概要设计与详细设计。

## Goals / Non-Goals

**Goals:**

- 在 `参考文档/0、模板/` 落两份可复用 Markdown 模板：概要设计、详细设计。
- 6 个菜单各产出 **概要设计 V1 + 详细设计 V1**，分别建版本文件夹（共 12 份）。
- 概要侧重：该菜单目标、范围、角色场景、在开课链路中的位置、主流程、边界与待确认。
- 详细侧重：该菜单页面结构、查询与列表、关键动作、校验规则、状态、数据对象（原型已知）、上下游依赖。

**Non-Goals:**

- 不合并成「开课设置+专业开课」总册。
- 不升版/覆盖现有 PRD 版本文件夹。
- 同步生成 md 与 docx（同版本文件夹内文件名一致）。
- 不实现或改动原型功能代码。
- 通识选修 / 特殊开课 / 开课清单不在本批菜单内（仅在上下游中提及）。

## Decisions

### 1. 产出粒度：每菜单各一份概要 + 一份详细

- **决定**：6 菜单 ×（概要设计 + 详细设计）= 12 份；每份独占版本文件夹。
- **理由**：用户确认「每个菜单一份，分别建文件夹」。
- **备选（已弃）**：合写总册 2 份。

### 2. 目录与命名

归档在既有一级/二级菜单目录下，与 PRD 并列、互不覆盖：

```
参考文档/2、开课管理/
  开课设置/
    开课时间设置/
      开课时间设置概要设计20260807V1/
        开课时间设置概要设计20260807V1.md
      开课时间设置详细设计20260807V1/
        开课时间设置详细设计20260807V1.md
    校选课程管理/ …（同上模式）
    特殊课程设置/ …（同上模式）
  专业开课/
    开课计划/ …（同上模式）
    开课安排/ …（同上模式）
    开课名单/ …（同上模式）
```

- 日期：创建当日；版本：各菜单设计文档各自从 V1 起。
- 禁止覆盖已有同名版本文件夹。

### 3. 模板章节（约定）

**概要设计模板：** 文档信息；建设目标与范围；角色与场景；在整体开课链路中的位置；主业务流程；职责边界；非功能期望（已知/待确认）；风险与待确认。

**详细设计模板：** 文档信息；设计约定；**业务流程图（角色泳道）**；**系统流程图（模块/菜单泳道）**；页面结构；查询与列表；关键动作；校验与规则；状态流转；数据对象；上下游与跨模块约束；异常与提示；待确认清单。  
（单菜单文档不再「按多模块分章」，改为单模块深写；跨模块只写与本菜单直接相关的依赖。流程图角色默认：教务负责人、学院负责人、老师；系统图按相关菜单/功能分泳道。图源：`scripts/draw-design-swimlanes.py` → `_设计图资产/详细设计泳道图*`。）

### 4. 内容来源优先级

1. 当前原型页面与交互  
2. 同菜单已有需求文档 / 操作流程图 / 变更说明  
3. 无法确认处写「待确认」

### 5. 语言

- 正文中文；菜单名、按钮文案与原型一致。  
- 界面本身为英文的文案可保留原文并加中文说明。

### 6. 跨菜单一致性

- 写专业开课三菜单时，统一写明：未完成授课确认不可提交到开课名单；授课确认管理入口在开课清单侧栏。  
- 开课设置三菜单写明对专业/通识的前置支撑关系（已知则写）。

## Risks / Trade-offs

- [文档数量多、重复叙述上下游] → 各文档只写与本菜单直接相关的上下游，其余用「见某某菜单设计文档」引用。  
- [原型与校方规则不一致] → 标明依据原型；政策类待确认。  
- [与 PRD 字段表重复] → 详细设计以规则与流程为主，字段引用 PRD/原型，不整表复制。
