# 批量调课管理 · 批量调课程改动方案

> 文档性质：代码改动方案（对照 `prototype/` 现状）。  
> 适用范围：仅 **批量调课管理列表入口按钮顺序** + **新开「批量调课程」流程**。  
> 状态：**待实现**（先方案、后改代码）。

---

## 0. 需求口径

用户描述：

1. 在批量调课界面，**「批量调教室」按钮前**增加 **「批量调课程」**。
2. 进入后：**按学期选择课程** → **按已选课程关联选择原日期、节次** → 再选 **目标日期、节次** → **生成调课明细** 后批量调课。
3. **「批量调时间」按钮改到「批量调教室」后面**。

与现网「批量调时间」的本质差别：

| | 现网「批量调时间」 | 本期「批量调课程」 |
|---|---|---|
| 起点 | 先选源日期、源节次 | **先按学期选课程（必选）** |
| 课程 | 可选筛选，不选不清课程 | **必选**，再由课程带出可选原日期/节次 |
| 原日期/节次 | 学期内自由勾选日历/星期 | **只能从已选课的已排课节里关联选择** |
| 目标 | 选目标日期、目标节次 | 同左：再选目标日期、目标节次 |
| 结果 | 生成明细 → 提交改星期/节次 | 同左（写回课表时间；可选顺带改教室） |

列表按钮目标顺序（从左到右）：

**批量调课程** → **批量调教室** → **批量调时间**

## 1. 已确认 / 待确认

### 已确认（按用户描述直接落地）

- 列表工具栏新增「批量调课程」，位置在「批量调教室」**之前**。
- 「批量调时间」挪到「批量调教室」**之后**。
- 课程侧流程：**学期 → 课程 → 关联原日期/节次 → 目标日期/节次 → 生成明细 → 提交**。
- 只出方案、先不改 `index.html` / `app.js` / `styles.css`（实现另开一轮）。

### 建议默认（实现前可再对一次）

| 项 | 建议 | 说明 |
|---|---|---|
| 抽屉形态 | 同一抽屉 `#modal-adjustment-batch` 新增 Tab「批量调课程」 | 与现网时间/教室一致，不另开独立抽屉 |
| 记录类型 | 新 `kind: 'course'`，列表展示「调课程」 | 与「调时间 / 调教室」并列，方便查询 |
| 学期 | 沿用列表查询「学年学期」`#adjustment-batch-filter-term` | 与时间/教室抽屉一致，打开时带入 |
| 原日期/节次 | 选项集合由已选课的已排课节推导，用户再勾选 | 「关联选择」，不是学期内任意日期 |
| 目标日期/节次 | 复用时间侧：按日期 / 按星期 + 节次多选 + 天数/节次数须相等 | 目标是「调到哪」，不必再受原课节集合限制 |
| 明细能力 | 复用时间侧：勾选、清空、删除、调教室、仅查冲突、冲突列、调后教室 | 减少两套表 |
| 提交写回 | 与「批量调时间」相同：改 `slot.weekday` / `periodFrom` / `periodTo`，有调后教室则一并写 `slot.room` | 「调课程」改的是这些课的上课时间，不是改课程号 |

### 待确认（方案按上表默认写，实现前如有不同再改）

1. **原侧交互**：  
   - **A（建议）**：选课后，原日期只列出这些课有课的日期（或对应星期），原节次只列出这些课在已选日期上出现过的节次。  
   - B：选课后直接列出「日期 + 星期 + 节次」课节清单，勾选要调的课节，不再分两步选日期/节次。  
2. **原侧是否保留「按日期 / 按星期」**：建议保留，但可选集合仍必须来自已选课已排课节。  
3. **多门课**：建议支持多选课程；原日期/节次为这些课已排课节的并集。  
4. **未排时间的课**：选课后若没有任何已排课节，提示「所选课程暂无已排课节」，禁止生成明细。

- 查询：学年学期 `#adjustment-batch-filter-term`，调课类型 `#adjustment-batch-filter-kind`（空 / `time` / `room`）。

### 3.2 抽屉

`#modal-adjustment-batch`

- Tab 仅两个：`#adjustment-batch-tab-time`、`#adjustment-batch-tab-room`。
- `openAdjustmentBatchDrawer(kind)` 现网：`kind === 'room' ? 'room' : 'time'`，**其它值都会落到时间 Tab**。本期若不改这句，「批量调课程」会误开时间页。

### 3.3 时间侧（对照，本期不改其内部）

- 源/目标日期（按日期 | 按星期）、源/目标节次、课程**可选**筛选。

- 提交改课节星期/节次，可选写调后教室。

### 3.4 教室侧（对照，本期不改其内部）

- 源日期 / 源节次 / 源教室 → 目标教室。
- 与课程优先流程无关。

### 3.5 记录与筛选

- `saveAdjustmentBatchRecord(kind, …)`，`kind` 现为 `time` | `room`。
- 列表类型列：`time` → 调时间，`room` → 调教室。

## 4. 目标交互

### 4.1 列表

1. 工具栏从左到右：**批量调课程**、**批量调教室**、**批量调时间**。
2. 「批量调课程」→ `openAdjustmentBatchDrawer('course')`。
3. 调课类型下拉增加：`<option value="course">调课程</option>`。
4. 副标题建议改为：`按课程、教室或时间批量调整已排课节`（或等价表述，需同时提到三种入口）。

### 4.2 抽屉 · 批量调课程（新 Tab）

标题建议：`批量调课程`。  
工具条提示建议：`先按学期选择课程，再从已选课程的已排课节中选择原日期、节次，最后指定目标日期、节次并生成调课明细`。

建议字段顺序（上 → 下）：

| 顺序 | 字段 | 必填 | 说明 |
|---|---|---|---|
| 1 | 课程（可搜索多选） | 是 | 选项来自当前学期课表任务，展示「课程号 课程名称」 |
| 2 | 原日期 | 是 | **可选项仅含已选课已排课节上的日期**；可保留按日期 / 按星期，但星期也只列出这些课出现过的星期 |
| 3 | 原节次（可多选） | 是 | **可选项仅含已选课在已选原日期上出现过的节次**；未选原日期时，可为这些课全部已排节次的并集 |
| 4 | 目标日期 | 是 | 复用时间侧：按日期 / 按星期，学期内可选（目标不受「原课节集合」限制） |
| 5 | 目标节次（可多选） | 是 | 与时间侧相同 |

规则：

- **未选课程**：原日期、原节次控件禁用或为空，提示「请先选择课程」。
- **已选课程但无已排课节**：原日期/节次为空，提示「所选课程暂无已排课节」。
- **改课程选择**：清空已选原日期/原节次、已生成明细（目标日期/节次可保留，避免误提交旧明细即可）。
- **改原日期**：重算原节次可选集合；已勾但不在新集合里的节次去掉。
- 目标日期个数须等于原日期个数，目标节次个数须等于原节次个数（与时间侧一致）。
- 多选时按顺位对应：第 N 个原日期 → 第 N 个目标日期，第 N 个原节次 → 第 N 个目标节次。

### 4.3 生成明细与提交

与时间侧对齐，仅数据来源改为「已选课程 ∩ 所选原日期/节次」：

- 「确定生成调课明细」：按顺位映射写出明细；无命中课节则提示。
- 「清空调课明细 / 删除调课明细」：行为对齐时间侧。
- 「调教室」：对勾选明细指定调后教室（建议复用现网时间侧弹窗，按 `course` 分支读写本 Tab 状态）。
- 「仅查询冲突数据」：只显示有冲突的行。
- 明细列建议与时间侧相同：勾选、序号、课程编号、课程名称、上课小组、教师、源日期、原节次、教室、调整后日期、调整后节次、调后教室、冲突情况、操作。
- 提交前：须已生成明细、须填调整原因；有冲突则禁止提交。
- 确认文案：`确认对 N 个课节执行「批量调课程」？`

### 4.4 与时间侧 Tab 的隔离

- 新面板 `#adjustment-batch-tab-course`，**不要**改 `#adjustment-batch-tab-time` 里课程字段的「可选、不选则不限制」语义。
- 时间侧仍然：先日期/节次，课程只是筛选。
- 教室侧完全不动。

## 5. 代码改动

### 5.1 `prototype/index.html`

**列表 `#page-adjustment-batch`**

1. 副标题按 4.1 改。
2. `#adjustment-batch-filter-kind` 增加 `value="course"` → 调课程。
3. 工具栏按钮顺序改为：

```html
<button … onclick="openAdjustmentBatchDrawer('course')">批量调课程</button>
<button … onclick="openAdjustmentBatchDrawer('room')">批量调教室</button>
<button … onclick="openAdjustmentBatchDrawer('time')">批量调时间</button>
```

**抽屉 `#modal-adjustment-batch`**

1. Tab 导航增加「批量调课程」，建议放在「批量调时间 / 批量调教室」之前（与列表入口顺序一致），`data-tab="adjustment-batch-tab-course"`。
2. 新增面板 `#adjustment-batch-tab-course`，结构可参考时间 Tab，但字段顺序按 4.2：
   - 课程多选：`#adjustment-batch-course-courses` + `#adjustment-batch-course-courses-mount`（hint：必选；选项随学期/已排课节变化）。
   - 原日期：`data-kind="course"` 的按日期/按星期 + 日历/星期挂载（id 前缀 `adjustment-batch-course-` / `course`）。
   - 原节次：`#adjustment-batch-course-source-periods`。
   - 目标日期：`data-kind="courseTarget"`（或本 Tab 内独立一套 target 状态）。
   - 目标节次：`#adjustment-batch-course-target-periods`。
   - 明细按钮：`generateAdjustmentBatchCoursePreview` / `clear…` / `delete…` / `openAdjustmentBatchCourseRowsPicker`。
   - 仅查冲突：`#adjustment-batch-course-conflict-only`。
   - 表体：`#adjustment-batch-course-preview-body`。
   - 原因 / 附件：`adjustment-batch-course-reason` 等。
3. **不要**改 `#adjustment-batch-tab-time`、`#adjustment-batch-tab-room` 内部现有控件 id 与文案。

### 5.2 `prototype/app.js`

**入口与 Tab**

- `openAdjustmentBatchDrawer(kind)`：显式识别 `'course' | 'room' | 'time'`，不要再写成「非 room 即 time」。
- `activateAdjustmentBatchTab`：增加 `adjustment-batch-tab-course`；切到课程 Tab 时初始化课程下拉、按已选课刷新原日期/节次可选集。
- 抽屉内三个 Tab 可互切；切走不丢本 Tab 已填（与现网时间/教室互切一致即可）。

**状态**

在 `ADJUSTMENT_BATCH_STATE` 增加 `course`（及如需的 `courseTarget`），建议字段：

- `dateMode` / 原日期集合 / 原星期（若保留按星期）
- `sourcePeriods`
- 目标侧同等字段
- `courseCodes`（必选）
- `preview`、`selectedIds`、`files`、`conflictOnly` 等（对齐时间侧）

**课程选项**

- 复用 `getScheduleTaskRows()`，按列表当前学期过滤（与打开抽屉时带入的学期一致）。
- 展示「课程号 课程名称」，可复用 `.adj-batch-ss-multi`。
- `onChange`：写入 `courseCodes`，调用「按课程刷新原日期/节次可选集」，并清空已生成明细。

**关联原日期 / 原节次（核心）**

新增函数（名称可调整），例如 `getAdjustmentBatchCourseSourceOptions(courseCodes)`：

1. 扫 `getScheduleTaskRows()` 中 `code` 落在已选课程内的任务。
2. 展开其已排 `slots`（需有星期、节次；能解析出具体日期的按日期收，按星期模式则收 weekday）。
3. 得到：
   - `allowedDates` / `allowedWeekdays`
   - `allowedPeriods`（可再按当前已选原日期收窄）
4. 渲染原日期日历/星期时，**不在集合内的日期禁用或直接不渲染**。
5. 渲染原节次时，只生成集合内的 checkbox。

`collectAdjustmentBatchHits` 对 `kind === 'course'`：

- **必须先按 `courseCodes` 过滤任务**（空课程直接无命中）。
- 再按所选原日期、原节次收课节。
- 不要走时间侧「课程为空则不过滤」的逻辑。

生成 / 映射 / 冲突：

- 可抽与时间侧共用的「天数相等、节次相等、顺位 zip、冲突文案」；或复制时间侧函数并改名为 `*Course*`。
- **不要**改 `generateAdjustmentBatchTimePreview` 的现有行为。
- 课程侧提交：`confirmAdjustmentBatch` 增加 `course` 分支，写回逻辑对齐 time，归档 `kind: 'course'`。

**记录列表**

- `saveAdjustmentBatchRecord`、`getAdjustmentBatchFilteredRecords`、类型徽章：`course` → 「调课程」。
- 详情抽屉若展示类型，同步加「调课程」。

**重置**

- `resetAdjustmentBatchForm('course')` 只清课程 Tab，不动 time/room。

### 5.3 `prototype/styles.css`

- 课程 Tab 尽量复用 `.adjustment-batch-*`、`.adj-batch-ss-multi`、`.adj-batch-date-mode`、明细表样式。
- 仅当「未选课禁用原日期/节次」需要额外态时，加课程 Tab 作用域类（例如 `#adjustment-batch-tab-course .is-disabled-until-course`）。
- **不要**改时间/教室 Tab 的专用选择器语义。

### 5.4 不改

- `#page-schedule-time-detail` / `#page-schedule-room-detail` 及共享右键 `#schedule-grid-context-menu`。
- `#adjustment-batch-tab-time`、`#adjustment-batch-tab-room` 的表单结构与提交语义（除非为认 `course` 在共享函数里加早返回）。
- 列表查询改成 4 个条件。

## 6. 校验与提示（课程 Tab）

| 时机 | 条件 | 提示 |
|---|---|---|
| 生成明细 | 未选课程 | 请先选择课程 |
| 生成明细 | 已选课但无已排课节 | 所选课程暂无已排课节 |
| 生成明细 | 未选原日期 / 原节次 | 请选择原日期 / 请选择原节次 |
| 生成明细 | 未选目标日期 / 目标节次 | 请选择目标日期 / 请选择目标节次 |
| 生成明细 | 原/目标日期个数不同 | 原日期与目标日期数量须一致 |
| 生成明细 | 原/目标节次个数不同 | 原节次与目标节次数量须一致 |
| 生成明细 | 无命中课节 | 当前条件没有可调整的课节 |
| 提交 | 未生成明细 | 请先点击「确定生成调课明细」 |
| 提交 | 未填原因 | 请填写调整原因 |
| 提交 | 明细有冲突 | 存在 N 条冲突，无法提交 |

时间 Tab、教室 Tab 的校验文案与逻辑保持现网。
