## Context

See proposal.md — Why。

现状：`page-course-ge-offering-quota` 上段 `#ge-offering-demand-card` 已有文/商/理人数摘要 + 按学院明细表；数据来自 `ensureGeOfferingDemand(termCode)` 演示汇总。培养方案/执行计划矩阵有「最高学分」字段，但本页本期**不读**矩阵，用写死学分档。

约束：原型假数据；刷新两 Tab 共用；Tab B 总人数与文商理三卡之和一致；标准学分 &lt; 2 剔除。

## Goals / Non-Goals

**Goals:**

- Tab：`按学院明细` | `GE学分分布预估`
- Tab B：文/商/理三卡片（总人数、2 学分人次、3 学分人次）
- 纯函数化拆分规则（固定档 + 50/50 偶数期望 + 奇数规则一），可单测/手算对齐验算示例
- 演示批次标准学分以 **4～7** 为主造数；规则表仍覆盖 2～11 以备特殊档

**Non-Goals:**

- 本期不做批次/学院明细第二张表
- 不对接执行计划「最高学分」真源
- 不改下段学院配额保存
- 不改交叉选课规则文案（文可选商理等）

## Decisions

### D1：UI 放在开课需求卡片内 Tab，而非新页面

- **选择**：卡片 body 顶部 Tab；摘要区在「按学院明细」保留；切到「GE学分分布预估」时隐藏学院表与现摘要，展示三列学分分布卡（或摘要区替换为三卡——实现时优先：Tab B 专属容器，避免打乱现有摘要 DOM）。
- **备选**：独立二级菜单页 → 否决（用户明确在需求卡片内切换）。

### D2：学分档写死在需求演示数据上，按批次带 `standardCredits`

- **选择**：在 `ensureGeOfferingDemand`（或并列构建函数）为每个演示专业批次挂 `standardCredits ∈ {4,5,6,7}`（可少量 2/3 仅当需要演示固定档时）；按 `PROGRAMME_GE_STREAM_MAP` 归文商理后累加。
- **备选**：全局按大类写死一个学分 → 否决（规格要求按批次分别算再累加）。

### D3：拆分算法独立为纯函数

- **选择**：`splitGeStandardCreditsToSeatCounts(standardCredits, headcount) → { seats2, seats3 }`；50/50 档奇数用 ⌈N/2⌉ / ⌊N/2⌋。
- **理由**：与 UI 解耦，便于对照验算示例。

### D4：人数一致性

- **选择**：Tab B 各类 `totalStudents` 取与现有 `demand.byStream.*` **同一套**批次人数汇总（剔除 standardCredits &lt; 2 后，演示数据须保证剔除后仍等于展示用文商理人数；造数时不放 &lt; 2 的批次，或剔除后同步从 byStream 扣除——**优先造数不含 &lt; 2**，代码仍实现剔除规则）。
- **刷新**：`refreshGeOfferingDemandPage` 重算 demand + 重绘当前 Tab。

### D5：标准学分档表（实现常量）

| 标准学分 | 模式 | 每人 2学分门数 / 3学分门数（或 A/B） |
|---------|------|--------------------------------------|
| 2 | 固定 | 1 / 0 |
| 3 | 固定 | 0 / 1 |
| 4 | 固定 | 2 / 0 |
| 5 | 固定 | 1 / 1 |
| 6 | 50/50 | A:3/0；B:0/2；期望 1.5 / 1 |
| 7 | 固定 | 2 / 1 |
| 8 | 50/50 | A:4/0；B:1/2；期望 2.5 / 1 |
| 9 | 50/50 | A:3/1；B:0/3；期望 1.5 / 2 |
| 10 | 50/50 | A:5/0；B:2/2；期望 3.5 / 1 |
| 11 | 50/50 | A:4/1；B:1/3；期望 2.5 / 2 |

偶数 50/50：`seats2 = N * expect2`，`seats3 = N * expect3`（须为整数）。奇数：规则一。

## Risks / Trade-offs

- [假数据与正式源不一致] → Mitigation：UI 保留「演示数据」标识；design/proposal 标明正式接最高学分另 change。
- [浮点期望值] → Mitigation：仅用 `.5` 期望 × 偶数 N，保证整数；奇数走整数分配。
- [Tab 切换状态丢失] → Mitigation：Tab 状态挂内存变量，刷新后保持当前 Tab。

## Migration Plan

纯前端原型；无数据迁移。回滚即移除 Tab/B 视图与拆分函数，恢复单表。
