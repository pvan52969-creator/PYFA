# Proposal

## Why

手动排时间缺少按场地类型的教室资源实时预警（售罄/超排），师生等冲突仍占用描边，无法一眼区分资源紧张；手动排课页也缺少「只导入当前待排」的一键导入，排教室导入亦未覆盖连堂异类型就近（Back-to-Back）。需要在手动排时间/排教室详情补齐资源检查与导入规则，且不动开课与自动排作业页。

## What Changes

- **排时间 · 教室资源检查**：选场地类型（含「不选择教室」）或点击左侧待排任务卡片后，右侧课表按类型+人数算容量区间，用描边标记未超排 / 售罄（红虚线）/ 超排（红实线）；资源态**独占描边、不填底色**。
- **冲突视觉解耦**：教师/学生/不排课等冲突**只保留底色**，去掉现有 inset 描边；冲突填色已改过的不再重做。
- **右键容量表**：查看所选时段适用区间的总数量/可用数量（0 与超排数字标红）。
- **容量占位口径**：先排人数最大与最小的任务，两端占满后中间人数再向上占位，避免小班占大教室；共同授课按合计人数占一席。
- **锁定取一**：专业/计算机偏好可多选仅参考，锁定只能 1 间（偏好内或相似偏好外）；无偏好可锁任意教室；普通教室也允许锁具体教室。
- **强行排入**：落点弹窗增加「强行排入」，仅允许忽略**场地/容量**强行排入同一场地路径；**学生时间冲突不可强排**。
- **一键导入（手动页）**：在手动排时间/排教室详情加入口；只导入**当前待排**任务；考虑场地类型资源。**不是**侧栏自动排课/自动排教室作业页。
- **排教室一键导入 · B2B**：连堂两节类型/偏好不同需两间教室；距离优先 `同教室 > 隔壁 > 同楼层 > 同楼栋 > 其他`；老师 Back-to-Back 优先于学生。

非目标：开课偏好；自动排课/自动排教室作业页与 `SCHEDULE_AUTO_STORE` 作业流；汇总排教室专项 UI；排课偏好菜单大改；联合排课双视窗同步（靠刷新看实时）。

## Capabilities

### New Capabilities

- `schedule-time-room-resource`: 手动排时间教室资源检查（描边三态、容量表、占位、锁定取一、强行排入）、手动页一键导入（当前待排）、排教室一键导入 Back-to-Back 就近规则；时间/教室两侧独立。

### Modified Capabilities

- （无）现有 `openspec/specs/` 能力未覆盖本行为，不修改既有 spec 路径。

## Impact

- 页面：`#page-schedule-time-detail`、`#page-schedule-room-detail`（clone 后补丁）；冲突图例 `#schedule-conflict-legend`；落点冲突/强排弹窗；手动详情工具区「一键导入」。
- 逻辑/样式：`app.js` 冲突上色与场地字段（`lockedRoom` / `preferredRooms` / venue types）、资源检查与导入 mock；`styles.css` 格子冲突 inset 与资源描边 class。
- 约束：遵守排时间/排教室产品面独立；不改教室独立右键菜单条目集合（除非容量表明确只挂时间侧）；不改自动排侧栏四页。
