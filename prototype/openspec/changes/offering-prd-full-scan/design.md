## Context

See proposal.md — Why。开课管理文档分两套树，侧栏与 PRD 覆盖不完全对齐。本设计只定文档治理做法，不改产品代码。

现行侧栏（`#sidebar-nav-course`）：

```
开课设置          专业开课         选修开课         课程班管理
├ 操作流程图      ├ 开课计划       ├ 选修开课计划   ├ 课程班
├ 开课时间设置    ├ 开课安排       ├ 选修开课安排   ├ Teaching Load
├ 校选课程管理    └ 开课名单       └ 选修开课名单   ├ 授课确认管理
└ 特殊课程设置                                     ├ 授课确认（教师端）
                                                   ├ 授课教师替换
                                                   └ 排课计划
```

侧栏已下线：特殊开课分组（改由专业开课计划「特殊开课」按钮）；共同授课维护、开课名单变更日志、合分班独立菜单。

## Goals / Non-Goals

**Goals:**

- 给每个现行二级菜单钉一份「最新 PRD 文件夹」
- 把 0807 树、变更说明里未勾选的「待确认」、以及真正未拍板的 UC 分开
- 列出必须客户拍板才能升版的问题
- 列出过期 OpenSpec，避免按旧 proposal 实现

**Non-Goals:**

- 不在本 change 重写 0807 概要/详细设计
- 不补写特殊开课独立 PRD（先确认入口是否长期下线）
- 不实现选修 UC、ME 借用方案 A/B
- 不改排课管理文档

### 2. 「待确认」两套含义不要混

```
┌─────────────────────────────────────────────────────────┐
│  变更说明表「确认状态」列 = 该次文档调整是否签核         │
│  多数 0807→V2 变更说明仍 □ 待确认，但后续 20260915      │
│  已把同一口径写成「已明确」——不要再拿 0807 表当未决     │
└─────────────────────────────────────────────────────────┘
                         vs
┌─────────────────────────────────────────────────────────┐
│  现行 PRD §11「未确认事项」= 产品规则尚未拍板            │
│  专业开课 / 开课设置 / 课程班 20260915：§11 写「本版无」 │
│  选修 20260915V1 仍有 UC                                 │
└─────────────────────────────────────────────────────────┘
```

## Risks / Trade-offs

- [有人仍打开 0807 详细设计开发] → 根目录 README + 规范索引双处标明过期
- [把变更说明未勾选当成产品未决] → 以现行 PRD §11 为准
- [按旧 OpenSpec 把类型配额再实现一遍] → 任务里显式对照 20260915V1，禁止重复发明
- [特殊开课入口被误删或误当独立模块] → 保持「计划页按钮、无 04 目录」直至客户确认

## Migration Plan

文档-only。无运行时迁移。回滚 = 还原本 change 新增的索引/README。
