# 排课表教室 · 课表冲突查询代码改动方案

> 文档性质：代码改动方案（需求修订版）  
> 适用范围：排课管理 · 排课表教室  
> 关联代码：`prototype/index.html`、`prototype/app.js`、`prototype/styles.css`  
> 状态：规则已确认 / 待实现

---

## 1. 改动目标

调整「排课表教室」二级菜单 page-id，并新增第三个二级菜单「课表冲突查询」。

目标菜单：

1. 按时间排：`schedule-room-week`
2. 按场地类型排：`schedule-room-category`
3. 课表冲突查询：`schedule-room-conflict`

课表冲突查询首期支持三类冲突：

1. 教室时间冲突
2. 座位人数冲突
3. 场地类型冲突

查询结果按具体冲突周逐周显示；同一节次涉及多门课程时按节次聚合；联排节次按完整联排范围及起止时间显示；支持导出当前查询结果。

## 3. 课表冲突查询页面

### 3.1 页面结构

新增独立页面：

```html
<section class="page schedule-page"
  id="page-schedule-room-conflict"
  hidden aria-hidden="true">
</section>
```

页面由以下区域组成：

1. 页头：标题「课表冲突查询」。
2. 副标题：查询排课教室阶段的教室时间、座位人数及场地类型冲突。
3. 查询条件区。
4. 查询结果统计提示条。
5. 导出按钮。
6. 横向滚动结果表格。
7. 空数据提示。

### 3.2 查询条件

查询字段：

1. 学年学期：必选，默认当前排课学期。
2. 冲突类型：全部、教室时间冲突、座位人数冲突、场地类型冲突。
3. 日期：日期选择器，查询指定自然日。
4. 周次：数字输入，查询指定教学周。
5. 星期：全部、周一至周日。
6. 节次：全部或指定节次。
7. 课程号 / 课程名称：模糊查询。
8. 教师工号 / 教师姓名：模糊查询。
9. 教室：模糊查询。
10. 查询按钮。
11. 重置按钮。

建议 DOM id：

```text
schedule-room-conflict-filter-term
schedule-room-conflict-filter-type
schedule-room-conflict-filter-date
schedule-room-conflict-filter-week
schedule-room-conflict-filter-weekday
schedule-room-conflict-filter-period
schedule-room-conflict-filter-course
schedule-room-conflict-filter-teacher
schedule-room-conflict-filter-room
schedule-room-conflict-body
schedule-room-conflict-hint
btn-schedule-room-conflict-export
```

### 3.3 日期、周次和星期联动

1. 输入日期后，根据学期首周周一计算教学周及星期，并自动回显周次、星期。
2. 输入周次和星期后，可计算并回显日期。
3. 日期超出当前学期教学周期时提示并不执行查询。
4. 日期与周次/星期同时填写但不一致时，以日期为准并重新计算。
5. 重置后保留当前学期，清空日期、周次、星期、节次等条件。

### 3.4 节次筛选

节次选项来自 `ensureSchedulePeriods(termCode)`，显示格式：

```text
第1节 08:00-09:00
第2节 09:00-10:00
```

筛选某一节时，只要课程联排区间覆盖该节次即命中。例如查询第 3 节，第 2-3 节和第 3-4 节均应返回。

## 4. 列表字段

按以下顺序展示：

1. 序号
2. 学期
3. 日期
4. 周次
5. 星期
6. 节次
7. 课程号
8. 课程名称
9. 上课教师
10. 上课小组（人数）
11. 上课教室
12. 共同授课状态
13. 冲突类型
14. 冲突内容

字段来源：

- 学期：当前 `termCode`，使用 `formatCourseTermDisplay(termCode)`。
- 日期：按学期首周、具体冲突周、星期计算。
- 周次：显示具体冲突周，如「第5周」，不显示课程完整的 `1-14周`。
- 星期：`getScheduleWeekdayLabel(slot.weekday)`。
- 节次：完整联排节次及起止时间。
- 课程号：`formatScheduleCourseCode(task.code)`。
- 课程名称：`task.name`。
- 上课教师：`getScheduleTaskTeacherEntries(task)`，格式为「姓名（工号）」。
- 上课小组（人数）：节次关联小组名称及人数合计。
- 上课教室：优先 `slot.room`，回退 `task.location`。
- 共同授课状态：`Y` / `N`。
- 冲突类型：三类冲突之一。
- 冲突内容：列出冲突原因、要求值、实际值及关联课程。

表格应使用 `.table-scroll`，设置足够的 `min-width`；课程名称、教师、小组和冲突内容允许换行。

## 5. 结果展示粒度

### 5.1 同一冲突逐周显示

冲突结果必须按周次展开：

```text
课程 A：1-8周
课程 B：5-12周
重叠周：5、6、7、8
```

列表分别生成第 5、6、7、8 周记录，并为每周计算准确日期。

建议新增：

```javascript
getScheduleDateByTeachingWeek(termStart, weekNo, weekday)
```

禁止只按完整周次字符串取首周日期，否则日期与冲突周不一致。

### 5.2 同一节次多课程按节次聚合

同一学期、日期、星期、节次、教室、冲突类型相同的多门课程按节次聚合为一个冲突组。

列表展示方式：

- 每个冲突组可显示一行主记录。
- 课程号、课程名称、教师、小组等字段以换行方式列出组内课程。
- 冲突内容按课程逐条列出。
- 可选增加展开/收起，展开后查看每门课程的独立课表信息。

聚合 key 建议：

```text
termCode
+ weekNo
+ weekday
+ periodFrom
+ periodTo
+ room
+ conflictType
```

注意：第 2-3 节与第 3-4 节虽然在第 3 节重叠，但各自联排范围不同。检测时属于同一重叠事件，展示时必须保留每门课程自身完整节次；冲突组标题可显示「重叠节次：第3节」。

## 6. 联排节次与起止时间

联排节次不拆分为单节记录。

展示规则：

```text
单节       第3节 10:00-11:00
两节联排   第3-4节 10:00-12:00
三节联排   第1-3节 08:00-11:00
```

时间来源：

1. `ensureSchedulePeriods(termCode)` 获取节次配置。
2. 开始时间取 `periodFrom` 对应节次的 `startTime`。
3. 结束时间取 `periodTo` 对应节次的 `endTime`。
4. 节次配置缺失时显示节次编号，时间显示 `—`。

建议新增：

```javascript
formatScheduleConflictPeriodWithTime(slot, termCode)
```

## 7. 冲突判定规则

### 7.1 教室时间冲突

两项或多项课程同时满足以下条件：

1. 学期相同。
2. 教室相同且非空。
3. 星期相同。
4. 节次区间重叠。
5. 周次存在交集。
6. 不是同一 `slot.id`。
7. 不属于允许共享的共同授课。

区间重叠：

```text
max(A.periodFrom, B.periodFrom) <= min(A.periodTo, B.periodTo)
```

冲突内容示例：

```text
教学楼C-201 在第3节同时安排 RM201、RM202
```

非排课占用（排考、借用、维护）若纳入本页面，也归类为教室时间冲突，并在内容中标明占用来源；首期可复用现有 `SCHEDULE_ROOM_NON_SCHEDULE_OCCUPANCY`。

### 7.2 座位人数冲突

判定：

```text
节次上课人数 > 教室有效座位数
```

人数口径：

1. 小组实际人数 `studentCount`。
2. 无实际人数时回退小组上限 `capacityLimit`。
3. 无小组时回退课程计划人数或课程名额上限。
4. 共同授课状态为 `Y` 的共享课堂，人数按同一共同授课组内所有小组人数求和后校验。

教室座位优先取：

```text
availableSeats → seats → capacity
```

冲突内容示例：

```text
共同授课小组人数 76 > 教室有效座位数 60，超出 16 人
```

### 7.3 场地类型冲突

判定：

1. 读取节次 `venueTypes` / `classroomTypes`。
2. 读取已排教室的 `roomType` / `classroomTypeZh` / `classroomType`。
3. 经现有场地类型映射后无交集，判定为冲突。
4. 节次未设置场地类型时不报冲突。
5. 场地类型仅为「不选择教室」时不报冲突。
6. 多选场地类型匹配任意一项即通过。

冲突内容示例：

```text
要求「计算机教室」，实际教室类型为「普通教室」
```

## 8. 共同授课状态

### 8.1 字段定义

新增或统一使用：

```javascript
jointTeachingStatus: 'Y' | 'N'
```

建议挂在实际排课节次或共同授课关系上，而不是只挂课程主数据：

```javascript
slot.jointTeachingStatus
```

含义：

- `Y`：该节次允许多门课程/小组共享同一教师、时间和教室。
- `N`：独立授课，正常参与冲突判定。

### 8.2 必须增加共同授课组标识

仅有 `Y/N` 无法判断哪些课程属于同一共同授课关系。若多项无关课程均为 `Y`，不能全部互相豁免。

因此建议同时提供：

```javascript
jointTeachingGroupId: 'JT-2026-0001'
```

只有同时满足以下条件才视为合法共享课堂：

1. `jointTeachingStatus === 'Y'`
2. `jointTeachingGroupId` 相同
3. 学期、周次、星期和节次匹配
4. 使用同一教室

合法共同授课组：

- 不产生组内教室时间冲突。
- 座位人数按组内全部小组人数合计校验。
- 场地类型按组内课程要求并集校验；教室满足任一要求还是全部要求需统一，本方案默认必须满足组内所有课程要求。
- 列表按节次聚合展示，状态列显示 `Y`。

若业务坚持只保留 `Y/N`，则必须复用现有合班/共享课堂关系 id 作为隐式分组键，不能仅凭 `Y` 豁免。

detectScheduleRoomTimeQueryConflicts(records)

结果只用于查询展示，不写回排课任务。

## 10. 查询、排序与统计

默认排序：

1. 日期升序。
2. 冲突开始节次升序。
3. 教室升序。
4. 冲突类型顺序：教室时间、座位人数、场地类型。
5. 课程号升序。

页面统计：

- 冲突组数。
- 涉及节次数。
- 涉及课程数。
- 涉及教室数。
- 三类冲突各自数量。

筛选只作用于已计算结果；排课数据、教室信息、节次配置或共同授课状态变化后，应使冲突缓存失效并重新计算。

## 11. 导出

### 11.1 导出范围

增加「导出」按钮，导出当前查询条件下的全部结果，不仅导出当前可视区域。

无查询结果时按钮禁用或提示：

```text
暂无符合条件的冲突数据可导出
```

### 11.2 导出格式

原型首期复用现有课表 CSV 下载方式，生成 UTF-8 BOM CSV，保证 Excel 打开中文不乱码。

建议函数：

```javascript
exportScheduleRoomConflictRows()
```

文件名：

```text
课表冲突查询_2026-2027学年第一学期_20260807.csv
```

导出字段与页面一致，但不导出操作列。聚合组需要拆成明细行导出，每门课程一行，补充：

- 冲突组编号
- 重叠节次
- 共同授课组编号

这样便于后续在 Excel 中筛选和追踪。

### 11.3 Excel 扩展

如必须导出 `.xlsx`，建议后续统一引入项目级 Excel 工具；本原型当前已有 CSV 导出能力，不建议仅为该页面单独引入第三方依赖。

## 13. 验收标准

1. 菜单 page-id 分别为 `schedule-room-week`、`schedule-room-category`、`schedule-room-conflict`。
2. 旧 `schedule-room-intake`、`schedule-room-teacher` 深链可兼容跳转。
3. 冲突查询支持三种冲突类型。
4. 查询条件包含日期和节次，并与周次、星期正确联动。
5. 查询指定节次时，覆盖该节次的联排课程可命中。
6. 同一冲突按每个重叠周分别显示，日期准确。
7. 同一节次涉及多门课程时按节次聚合，仍可查看每门课程信息。
8. 联排节次显示完整节次范围和首尾起止时间。
9. 教室时间冲突能识别课程占用及非排课占用。
10. 座位人数冲突使用小组人数，合法共同授课组按人数合计校验。
11. 场地类型冲突正确处理多选类型和「不选择教室」。
12. 共同授课状态显示 `Y/N`；只有同一共同授课组的 `Y` 记录可豁免组内教室时间冲突。
13. 导出内容与当前查询结果一致，聚合结果按课程明细行导出。
14. 无结果时显示空状态且不能导出空文件。
15. 页面只用于查询和导出，不直接修改排课数据。
