# 调课申请管理 · 代发起前选择教师

日期：2026-11-25  
状态：已实现

## 背景

「调课申请管理」(`#page-adjustment-admin`) 上方「代发起调课 / 停课 / 补课 / 加课」目前可直接打开申请抽屉。管理端打开时左栏课表未强制按某一教师过滤（`getAdjustmentSlotRows` 在 `adjustmentAdminMode` 下 `teacherId` 为空），与「代某位教师按本人课表发起」的产品预期不符。

查询区已有「代申请教师」(`#adjustment-admin-teacher`)，但语义是**列表筛选**（可「全部」），不宜与代发起强绑。

## 目标

1. 四个「代发起*」按钮：先打开独立弹窗选择教师，确认后再进入申请抽屉。
2. 申请抽屉左栏（上课节次 / 停课记录等）按**本次所选教师**过滤。
3. 提交申请时，申请人使用本次所选教师；**不**回写查询区「代申请教师」。
4. 可选教师范围为排课教师库全量（含本学期无课）。

## 非目标

- 不改教师端「我的调课申请」发起流程。
- 不改变查询区「代申请教师」的列表筛选语义（仍可「全部」）。
- 不改排课时间 / 排教室页。
- 不复用或改造「调后教师」选择器 `#modal-adjustment-teacher-picker`（多选 + 追加/覆盖）。
- 不走 OpenSpec（单页交互小改，直接实现）。

## 方案（已选）

**方案 1：独立「选择代申请教师」弹窗**（已确认）。

备选已否决：

- 强制依赖查询区「代申请教师」：与「列表可看全部」冲突。
- 复用 `#modal-adjustment-teacher-picker`：职责与交互（多选/追加/覆盖）不匹配。
- 申请抽屉内再选教师：与已确认的「点按钮先选人」流程不符。

## 交互

```
点「代发起调课/停课/补课/加课」
  → 打开 #modal-adjustment-admin-proxy-teacher（记下本次 type）
  → 可按工号 / 姓名筛选，表格单选一名教师
  → 未选点确定 → 提示并拦截
  → 确定 → 关闭选人弹窗
       → 写入 adjustmentActiveTeacherId（仅内存，不改 #adjustment-admin-teacher）
       → openAdjustmentApplyModal(type, true)；左栏按该教师过滤
  → 取消 / 关闭选人 → 不打开申请抽屉
```

取消选人、提交或关闭申请抽屉后，均不回写列表筛选。

## 弹窗 UI

- 新弹窗：`#modal-adjustment-admin-proxy-teacher`（居中小窗，非抽屉）。
- 标题随类型，例如「选择代申请教师 · 调课」。
- 筛选（一行最多 4 条件 + 第 5 列按钮）：教师工号、教师姓名（输入框模糊匹配）；查询 / 重置。
- 列表列：单选 | 教师工号 | 教师姓名 | 所在单位 | 教职工类型。
- 数据：`getScheduleTeacherGroupRows()` 全量。
- 底部：取消 / 确定（须已单选）。

## 实现要点（指导实现，非任务清单）

- `openAdjustmentAdminApplyModal(type)`：改为先开选人弹窗并暂存 type；确认后再 `openAdjustmentApplyModal(type, true)`。
- 管理端同源列表（`getAdjustmentSlotRows` 及停课/补课等）：`adjustmentAdminMode` 时也按 `adjustmentActiveTeacherId` 过滤。
- 提交：继续用本次 `adjustmentActiveTeacherId` 作为申请人；删除「提交后回写 `#adjustment-admin-teacher`」时用注释保留原逻辑并说明原因（列表筛选与代发起解耦）。
- 不物理删除原有可运行代码路径；新增方法加简单注释（作用 / 参数）。
- 最小化改动：不扩散改教师端与其它调课页。

## 验收

1. 未选教师时点任一「代发起*」只出选人弹窗，不进申请抽屉。
2. 选人弹窗可按工号/姓名查询；未单选点确定有提示。
3. 确定后申请抽屉左栏仅为该教师相关节次/停课记录（无课时可为空列表）。
4. 查询区「代申请教师」在选人前后保持不变（含「全部」）。
5. 提交后的申请记录申请人 = 本次所选教师；教师端发起流程行为与改前一致。
