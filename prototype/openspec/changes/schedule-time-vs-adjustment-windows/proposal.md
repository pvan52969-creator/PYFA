# Proposal

## Why

排课模块设置里的「时间设置」目前是单一开关，与「排课时间设置」中的教师使用开放时间 / 学生查看开放时间未划清职责。三组互锁下，开放调课权限时会强制禁用「时间设置」；若把教师调课开放窗口也绑在该开关上，调课阶段会出现「模块开了但时间闸失效/无法配置」的歧义。需要先钉死：排课约束时间与门户开放时间是否分轨，以及调课是否需要独立时间控制。

## What Changes

- 明确「时间设置」（模块权限）只约束**排课侧**时间规则是否生效（学期窗口、不排课/占位等），不充当调课申请开关。
- 明确「调课管理」只做**调课模块开/关**；教师能否发起调/停/补/加课，由调课权限开放 **且** 「教师使用开放时间」窗口决定。
- 明确「学生查看开放时间」只约束学生课表查看，与调课申请无关。
- 产品文案：模块列「时间设置」更名或加注为「排课时间约束」，避免与门户开放时间混淆。
- 原型：互锁 tip / 表头说明对齐上述语义；教师/学生开放时间在调课权限开放时仍可维护并生效（不因 timeSetting 禁用而失效）。
- **不**新增第二列「调课时间设置」（除非后续产品明确要管理员一键忽略教师窗口）。

## Capabilities

### New Capabilities

- `schedule-portal-open-windows`: 教师使用开放时间、学生查看开放时间与模块「时间设置」的职责切分及调课/查看生效条件。

### Modified Capabilities

- （无）主库 `openspec/specs/` 尚未归档 `schedule-module-setting`；本变更以新能力描述窗口语义，并在 design 中约定与既有三组互锁的兼容关系。

## Impact

- 产品语义：`#page-schedule-module-setting` tip / 列名；`#page-schedule-time-setting` 教师/学生开放时间字段说明。
- 原型逻辑：`isScheduleModuleDisabled('timeSetting')` 的消费边界；教师门户调课入口与课表查看的窗口校验（若尚未接线，本变更定义契约并做最小示意）。
- 不改三组互锁主规则（开放调课仍强制禁用时间设置 + 排课权限）。
- 不改排时间 / 排教室详情交互；不改教室开放时间设置（审批用）职责。
