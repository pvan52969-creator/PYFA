# 课表查询 · 教师课表筛选条件代码改动方案

> 文档性质：代码改动方案（需求文档，供实现前对齐）  
> 适用范围：排课管理 · 课表查询 · **教师课表** Tab  
> 关联代码：`prototype/index.html`、`prototype/app.js`、`prototype/styles.css`  
> 参考现网：  
> - 教师课表 Tab：`#tab-schedule-teacher-timetable`  
> - 教师排课时间列表筛选：工号 / 姓名 / 所属学院 / 教职工类型  
> - 教师排课时间新增弹窗花名册：`schoolCode` / `staffType` / `title`  
> 状态：待确认 / 待实现

---

## 1. 改动目标

在「课表查询 → 教师课表」查询区增加（并拆开）以下条件：

1. **教师工号**
2. **教师姓名**
3. **所属学院**
4. **教职工类型**
5. **职称**

查询后仍展示该教师的图形课表；条件用于圈定教师范围，而不是改课表格子结构。

非目标（本期不做）：

- 不改学生课表 / 入学批次课表 / 课程课表 / 教室课表 / 时间课表的查询字段。
- 不改教师课表密度页。
- 不改排课表时间 / 排课表教室两侧交互。
- 不做按学院汇总多教师课表并排展示（多名命中时的展示见 §3.3）。

---

## 2. 现状

`#tab-schedule-teacher-timetable` 当前查询字段：

| 字段 | DOM | 说明 |
| --- | --- | --- |
| 学年学期 | `#schedule-teacher-tt-term` | 只读，当前开课学期 |
| 教师 | `#schedule-teacher-tt-teacher` | 单选下拉，选项来自已排课教师 |
| 排课周次 | `#schedule-teacher-tt-week` | 数字，可空 |

查询：`queryScheduleTeacherTimetable()` 读取下拉值写入 `scheduleTeacherTimetableKey`，再 `renderScheduleTeacherTimetableGrid()`。

教师选项：`getScheduleTimetableTeacherOptions()` 目前仅有 `id` / `name`，**无学院、类型、职称**。

---

## 3. 查询区调整

### 3.1 字段（建议）

保留学年学期、排课周次；**去掉「教师」单选下拉**，改为：

| 字段 | DOM 建议 id | 控件 | 说明 |
| --- | --- | --- | --- |
| 学年学期 | `schedule-teacher-tt-term` | 只读 | 不变 |
| 教师工号 | `schedule-teacher-tt-id` | 文本 | 模糊包含，可空 |
| 教师姓名 | `schedule-teacher-tt-name` | 文本 | 模糊包含，可空 |
| 所属学院 | `schedule-teacher-tt-school` | 下拉 | 全部 + 学院代码 |
| 教职工类型 | `schedule-teacher-tt-staff-type` | 下拉 | 全部 + 类型 |
| 职称 | `schedule-teacher-tt-title` | 下拉 | 全部 + 职称枚举 |
| 排课周次 | `schedule-teacher-tt-week` | 数字 | 不变 |

操作仍为：查询、重置。

筛选关系：**AND**；空值不约束。工号/姓名为包含匹配（大小写不敏感）。

下拉选项来源与教师排课时间新增弹窗对齐：

- 学院：花名册 `schoolCode` 去重（可辅以 `OFFERING_UNIT_CODES`）
- 教职工类型：花名册 `staffType` / `TEACHER_TYPE_CODES`
- 职称：`SCHEDULE_TEACHER_TITLE_CODES` + 花名册 `title` 去重

### 3.2 教师数据口径

查询候选教师仍为「本学期有已排课节次」的教师（与现 `getScheduleTimetableTeacherOptions` 一致），但每条需补齐筛选字段。

建议扩展选项结构：

```text
{ key, id, name, schoolCode, staffType, title }
```

字段回填优先级（与 `toScheduleTeacherRosterEntry` / `getScheduleTeacherGroupRows` 一致）：

| 字段 | 来源 |
| --- | --- |
| schoolCode | 任务/开课单位 → pool.departmentCode |
| staffType | meta.staffType → pool.teacherType |
| title | pool.title → meta.title → 演示职称补齐 |

### 3.3 查询结果（多名教师）

教师课表一次只画 **一名教师** 的格子。多名命中时：

1. 查询区下方增加结果条：`查询到 N 名教师`。  
2. 以可点选列表 / 标签展示命中教师（工号 + 姓名）。  
3. 默认选中第一名，渲染其课表。  
4. 点击其他教师切换课表，不改变筛选条件。  
5. 0 名：课表清空，提示「未找到符合条件的教师」。  
6. 1 名：直接出课表，结果条可简化为当前教师。

`scheduleTeacherTimetableKey` 继续表示「当前展示的教师工号」。

### 3.4 重置

- 工号、姓名清空；学院 / 类型 / 职称恢复「全部」；周次清空。  
- 当前选中教师与课表清空，提示「请填写条件后查询」。

### 3.5 导出

图形课表 / 数据课表仍导出 **当前选中教师** 的课表（与现逻辑一致），不导出筛选范围内全部教师。

## 4. 代码改动清单

### 4.1 `index.html`

仅改 `#tab-schedule-teacher-timetable` 查询区：

- 删除 `#schedule-teacher-tt-teacher`。  
- 增加工号、姓名、学院、类型、职称。  
- 查询区与课表之间增加结果条容器，例如：

```text
#schedule-teacher-tt-hint          （可沿用；若无则新增）
#schedule-teacher-tt-result-list   （多名命中时的教师切换）
```

现状 HTML 无 `#schedule-teacher-tt-hint`，但 `renderScheduleTeacherTimetableGrid` 已读写该节点。本期一并补上 hint + 结果列表，避免提示写空。

### 4.2 `app.js`

| 能力 | 现函数 | 改动 |
| --- | --- | --- |
| 教师选项 | `getScheduleTimetableTeacherOptions` | 补 `schoolCode` / `staffType` / `title` |
| 下拉填充 | `rebuildScheduleTeacherTimetableSelect` | 改为 `fillScheduleTeacherTimetableFilterOptions`（学院/类型/职称） |
| 读筛选 | （无） | 新增 `getScheduleTeacherTimetableFilters` |
| 过滤 | （无） | 新增 `filterScheduleTeacherTimetableOptions(opts, filters)` |
| 查询 | `queryScheduleTeacherTimetable` | 按筛选命中集合；默认选第一人；刷新结果列表与课表 |
| 切换 | （无） | 新增 `selectScheduleTeacherTimetableTeacher(id)` |
| 重置 | `resetScheduleTimetableQuery('teacher')` | 清新增字段与选中教师 |
| 渲染页 | `renderScheduleTeacherTimetablePage` | 进入 Tab 时填充筛选项，不再重建教师下拉 |

### 4.3 `styles.css`

结果列表轻量样式即可，例如横向标签：

```css
.schedule-teacher-tt-result-list {
  display: flex;
  flex-wrap: wrap;
  gap: 6px;
  margin: 0 0 8px;
}
.schedule-teacher-tt-result-chip.is-on { /* 当前展示教师 */ }
```

查询字段变多后，沿用 `.schedule-query-fields` 换行，无需新布局类（过挤再加 `schedule-query-fields-wide`）。
