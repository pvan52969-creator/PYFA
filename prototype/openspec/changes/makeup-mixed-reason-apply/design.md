## Context

补课抽屉右侧只有一组原因类型 / 事由 / 附件 / 请假记录，且 `makeup` 时只读、从停课记录继承。`getAdjustmentMakeupInheritedReason` 在原因类型不一致时返回失败；类型一致时只取第一条停课的事由和附件。左侧合并行（同一时间教师多课）可能把不同停课塞进一条勾选。

原因类型决定：是否必填事由、是否必传附件、是否要选 Academic-Related 请假记录。一张申请混多种类型，审批和材料规则对不上。

## Goals / Non-Goals

**Goals:**

- 继承判定覆盖「勾选的全部停课记录」（含合并行拆开后的成员）
- 不同类型：冲突可见、不能提交、提示分批
- 同类型：事由去重合并展示，附件并集，一张单可提交
- 列表 Apply 与抽屉内勾选共用同一套规则

**Non-Goals:**

- 不在一次提交里自动拆成多张补课申请
- 不让教师在补课单上改原因类型/事由（仍只读继承）
- 不改调课/停课/加课的自填原因
- 不改排时间 / 排教室详情

## Decisions

### 1. 一张补课单 = 一种原因类型，不混装

- **选择**：不同类型必须分批申请。不在一张单上做多组原因字段，也不一次提交拆多单。
- **备选**：一单多原因 → 附件必传/请假记录无法对整单生效。
- **备选**：一次点击按类型拆成 N 张申请 → 本期不做，避免审批列表与草稿状态变复杂。

### 2. 同类型、不同事由：合并而不是取第一条

- **选择**：事由按去重后的文本罗列（只读，可用换行或分号）；附件按文件名去重并集；请假记录若多条且不同，展示已关联的去重列表（Academic-Related 时）。
- **备选**：同类型也要求事由完全一致才允许提交 → 过严，公假日无事由、病假证明文案略有差别都会被拦。
- 类型是否相同：用 `reasonTypeCode`，没有则回退 `reasonType` 名称。

### 3. 冲突时右侧仍展示字段，用提示说清

- **选择**：原因类型只读框显示「原因类型不一致」类文案；事由区展示各停课的类型/事由摘要；hint 写明请按相同原因类型分批申请。提交仍 alert 拦截。
- **备选**：维持现在清空字段 → 教师看不到勾了什么冲突。

### 4. Apply 入口预检

- **选择**：补课页已勾选多条、原因类型已不一致时，点 Apply 先提示，**仍打开抽屉**并进入冲突态（方便改勾选），不要静默打开空白单。
- 抽屉内改勾选立即重算继承结果。

## Risks / Trade-offs

- [合并行藏了不同类型] → 继承必须 `expandAdjustmentSlotVal` 后对每条停课记录比类型，不能只看左侧一行。
- [合并后的事由偏长] → 只读 textarea，不截断到看不清。
- [教师期望一键全补] → 文案明确「按原因类型分批」；自动拆单留后续。

## Migration Plan

原型无数据迁移。回滚即恢复「类型不一致则清空 + 同类型取第一条」。
