# Proposal

## Why

联合排课当前把「专业批次 / 教师 / 公共选修课类型」放在同一筛选栏，允许批次与教师混选后查询。排课员难以判断本次联合对象是哪一类维度，也容易把不同维度对象混在一张表上。需要先选定单一对象类型，再只选同类对象。

## What Changes

- **BREAKING**：侧栏每次点击「联合排课」先弹出类型选择弹窗，三选一：
  - **按课程**
  - **按教师**
  - **按入学批次**
- 选定后进入联合排课页；**页内可再切换类型**，切换时**清空已选对象与该类无关筛选**。
- 同一时刻只允许一种对象类型；**不可**批次与教师混选，也**不可**课程与教师/批次混选。
- 筛选栏随类型变化：
  - **按入学批次**：学年学期 + 专业 + 专业批次；**不含**公共选修课类型。
  - **按教师**：学年学期 + 教师单位 + 教师。
  - **按课程**：学年学期 + 所属学院 + 所属专业 + 课程类型 + 公共选修课类型 + 本学期已开课程班（可直接多选）；公共选修课类型**仅挂在按课程**。
- 查询确定后，课表对象轴仅对应当前类型（批次行 / 教师行 / 课行）。

## Capabilities

### New Capabilities

- `schedule-joint-object-type-modes`：联合排课入口类型弹窗、页内类型切换、三类互斥筛选与对象选择、筛选栏随模式变化

### Modified Capabilities

- `schedule-joint-ge-object`：原「批次/教师与 GE 课对象可在同一次查询并存」改为仅在「按课程」模式下以课为对象（含 GE）；按入学批次 / 按教师模式不再混入课对象或公共选修课类型筛选

## Impact

- `index.html`：类型选择弹窗；联合排课筛选条结构（或由脚本重建）
- `app.js`：`launchScheduleJointTab` / `openScheduleJointPage`、筛选草稿与 applied 状态、确定查询与对象构建（`getScheduleJointUnionTasks` / `getScheduleJointRowObjects` 等）
- `styles.css`：类型弹窗与模式切换条样式
- **不改**：按入学批次排 / 按教师排 / 按课程排独立列表页；排教室路径；联合排课演示页是否跟进另议（本变更默认不强制改演示页）
