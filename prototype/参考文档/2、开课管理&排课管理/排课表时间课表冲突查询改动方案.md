# 排课表时间 · 课表冲突查询代码改动方案

> 文档性质：代码改动方案（需求文档，供实现前对齐）  
> 适用范围：排课管理 · **排课表时间**（第四个二级菜单）  
> 关联代码：`prototype/index.html`、`prototype/app.js`、`prototype/styles.css`  
> 关联说明：`排课与排教室冲突类型说明.md`  
> 对照实现：排课表教室 · 场地冲突查询（`#page-schedule-room-conflict`，仅作交互参照，**禁止改教室侧**）  
> 状态：**口径已确认 / 已实现**

---

## 1. 改动目标

在「排课表时间」下增加**第四个**二级菜单「课表冲突查询」。

目标菜单：

1. 按入学批次排：`schedule-time`
2. 按教师排：`schedule-teacher`
3. 按课程排：`schedule-course`
4. **课表冲突查询：`schedule-time-conflict`（新增）**

页面职责：

- 查询**已排课表**中仍存在冲突的节次数据。
- **包含忽略冲突后强制落点**的节次（不排课 / 教师排课时间 / 先修 / 预重修 / 学时超排 / 午休 / 排课规则等）。
- 查询条件须支持按**冲突类型**过滤（可与其它条件组合）。
- 只查不改：不在本页撤销、改排或写回课表。

---

## 2. 非目标

| 不做 | 说明 |
|------|------|
| 不改排课表教室 | 教室侧「场地冲突查询」保持原样；不改菜单、文案、筛选项、检测函数 |
| 不改排时间 / 排教室工作台 | 落点弹窗、格子着色、右键菜单、忽略冲突按钮逻辑本页不改 |
| 不查教室三类冲突 | 教室时间 / 座位数 / 场地类型只属于教室侧 |
| 不做冲突处理操作列 | 本页无「去排课 / 撤销」入口（如需跳转详情，二期再加） |

两侧独立性：教室侧需求不得改本页；本页不得改 `#page-schedule-room-conflict`、`#schedule-room-grid-context-menu` 或教室检测函数。可**只读复用**已有通用工具（日期换算、节次时间格式化）。

## 3. 现状可复用点

### 3.1 导航

`index.html`「排课表时间」现仅三项：

```text
按入学批次排   schedule-time
按教师排       schedule-teacher
按课程排       schedule-course
```

`SCHEDULE_PAGE_IDS` 尚未登记 `schedule-time-conflict`。  
教室侧已有独立页 `schedule-room-conflict`（标题现为「场地冲突查询」），交互可对照，代码须新开一套 `schedule-time-conflict-*`。

### 3.2 时间侧冲突检测（已有）

| 能力 | 函数 | 本页用法 |
|------|------|----------|
| 落点/已排格检测 | `detectSchedulePlaceConflicts` | 对已排节次重跑，得到师生 / 占位 / 先修等 |
| 已排格着色扫描 | `getScheduleOccupiedTimeConflictCellKeys` | 扫描口径参照；本页按节次展开，不按格子 Map |
| 教师不排课/只排课 | `detectScheduleTeacherSlotSoftConflicts` | 忽略落点后仍能检出 |
| 先修 / 预重修 | `detectSchedulePrereqConflicts` / `detectScheduleRetakeConflicts` | 预重修仅在有检测结果或节次本身可判定时纳入 |
| 午休 / 排课规则 | `detectScheduleRulePlaceConflicts` | 忽略落点后仍可重检 |
| 学时超排 | `detectScheduleHoursPlaceConflicts` | 忽略落点后仍可重检 |
| 硬/软可否继续 | `canForceSchedulePlaceDespiteConflicts` | 解释「忽略冲突插入」范围，本页不调用落点 |
| 日期 / 联排时间 | `getScheduleDateByTeachingWeek`、`formatScheduleConflictPeriodWithTime` | **只读复用**，不改教室页调用方 |

### 3.3 「忽略冲突插入」现状

强制继续排课（`handleSchedulePlaceConflictDecision` → 继续排课）**不会**在 `slot` 上写入 `ignoredConflicts`。  
忽略后节次已写入课表，占位类冲突在已排格上仍会着色（见 `detectSchedulePlaceConflicts` 注释）。

本页口径：**对已排节次重新检测**即可覆盖「忽略后仍冲突」的数据，不必依赖落点当时是否点了「继续排课」。

可选增强（非首期必须）：强制落点时写 `slot.ignoredConflictKinds = ['blackout', …]`，列表增加「忽略插入」列。首期不做落点写标记，避免改排时间工作台。

## 5. 页面结构

对照教室侧查询页，时间侧独立一套 DOM：

1. 页头：标题「课表冲突查询」；副标题「查询已排课表中的时间侧冲突（含忽略冲突后仍存在的冲突）」。
2. 查询条件区 + 查询 / 重置。
3. 统计提示条 `#schedule-time-conflict-hint`。
4. 导出（可选，与教室侧对齐；首期建议做）。
5. 结果表 `#schedule-time-conflict-body`。
6. 空数据提示。

建议 DOM id 前缀一律 `schedule-time-conflict-`，禁止复用 `schedule-room-conflict-*`。

## 6. 查询条件

| 字段 | 控件 | 说明 |
|------|------|------|
| 学年学期 | 只读 | 当前排课学期，`formatCourseTermDisplay` |
| **冲突类型** | 下拉 | **必做**。全部 + 下表各类型 |
| 日期 | date | 与周次、星期联动（复用教室侧同一换算规则） |
| 周次 | number | 指定教学周 |
| 星期 | 下拉 | 全部 / 周一～周日 |
| 节次 | 下拉 | `ensureSchedulePeriods`；联排覆盖该节即命中 |
| 课程号 / 名称 | 文本 | 模糊 |
| 教师工号 / 姓名 | 文本 | 模糊 |
| 学院 / 专业 / 入学批次 | 下拉 | 建议有，与「按入学批次排」筛选同源；可二期 |

**冲突类型选项（时间侧，不含教室三类）：**

| value | 标签 | 来源字段 | 格子着色 | 可否忽略落点 |
|-------|------|----------|----------|----------------|
| `teacher` | 教师冲突 | `conf.teacher` | 是 | 否（硬） |
| `student` | 学生冲突 | `conf.student` | 是 | 否（硬） |
| `blackout` | 不排课时间 | `conf.blackout` | 是（占位） | 是 |
| `elective` | 选修课占位 | `conf.elective` | 是（占位） | 通常不可真正落点 |
| `teacherSlot` | 教师排课时间 | `conf.teacherSlot` | 是（占位） | 是 |
| `prereq` | 先修冲突 | `conf.prereq` | 是 | 是 |
| `retake` | 预重修冲突 | `conf.retake` | 是 | 是 |
| `lunch` | 午休规则 | `conf.lunch` | 否 | 是 |
| `rule` | 排课规则 | `conf.rule` | 否 | 是 |
| `hours` | 学时超排 | `conf.hours` | 否 | 是 |
| `composite` | 综合冲突 | 同一节次命中 ≥2 类 | 品红 | 以最严为准 |

筛选「综合冲突」：只出多类型并存的行。  
筛选单一类型：该节次**含有**该类型即命中（综合行在筛「教师冲突」时仍应出现，冲突类型列可显示「综合冲突（含教师）」或拆成多行，见 §8）。

日期 / 周次 / 星期联动、越学期提示、重置保留学期：照抄教室侧已实现规则，函数名用 `onScheduleTimeConflictDateChange` 等，内部可抽一小段共享换算，**不要改** `onScheduleRoomConflictDateChange`。

## 7. 列表字段

建议列序：

1. 序号  
2. 学期  
3. 日期  
4. 周次（冲突当周，如「第5周」，不是课程完整 `1-14周`）  
5. 星期  
6. 节次（完整联排 + 起止时间，复用 `formatScheduleConflictPeriodWithTime`）  
7. 课程号  
8. 课程名称  
9. 上课教师  
10. 上课小组（人数）  
11. 冲突类型（标签色与时间侧图例一致）  
12. 冲突内容  
13. （可选）是否忽略插入：首期可用「可忽略类型且节次仍在」推断为「是」；硬冲突显示「—」或「否」

不展示教室侧专用列：上课教室、共同授课状态、座位数/场地类型。共同授课码仅用于检测时豁免教师冲突，不必单独成列。

## 8. 结果粒度

与教室侧查询对齐：

1. **按重叠周展开**：周次交集每周一行，日期用 `getScheduleDateByTeachingWeek`。  
2. **联排不拆单节**：第 2–3 节显示完整范围；筛「第3节」仍命中。  
3. **同格多课**：同一学期 + 日期 + 星期 + 联排节次 + 冲突类型 可聚合，课程/教师/内容换行列出。  
4. **多类型**：默认按**细类拆行**（同一节次教师+占位 → 两行，便于按类型过滤）；统计条另计「涉及节次数」。若产品更想一行综合，筛类型时再拆——**建议默认拆细类**，综合只作为筛选项/统计。

默认排序：日期 → 节次 → 冲突类型顺序（上表）→ 课程号。

## 9. 冲突判定（已排节次）

### 9.1 扫描范围

```text
getScheduleTaskRows()
  → normalizeTaskTimeSlots(task)
  → 有 weekday + periodFrom 的已排节次
```

对每个节次：

```javascript
detectSchedulePlaceConflicts(allTasks, task, weekday, periodFrom, weeks, room, {
  excludeSlotIds: new Set([slot.id])
})
```

并**额外合并**（已排格着色未纳入、但「忽略后仍冲突」需要）：

```javascript
detectScheduleRulePlaceConflicts(...)   // lunch / rule
detectScheduleHoursPlaceConflicts(...)  // hours
```

`scheduleDetailPhase` 在本页渲染时应视为 `'time'` 或检测时强制走时间侧分支，避免教室三类被算进来。

预重修：无「重修检测进行中」上下文时，仅当 `detectScheduleRetakeConflicts` 对已排节次仍能独立判定时纳入；否则首期可不出 `retake` 行，筛选项保留但结果为空并在副标题注明。

### 9.2 必须包含「忽略冲突插入」

下列类型允许强制落点，落点后课表上仍在，重检应出结果：

- 不排课时间、教师排课时间、先修、预重修  
- 午休规则、排课规则、学时超排  

教师 / 学生为硬冲突，正常流程不能忽略插入；若历史数据或调课后出现重叠，**仍应查出**。

共同授课码相同：组内**不报**教师冲突（与落点一致）。

### 9.3 结果行模型

```javascript
{
  id, termCode, termLabel,
  date, weekNo, weekLabel, weekday, weekdayLabel,
  periodFrom, periodTo, periodLabel,
  courseCode, courseName, teacherLabel, groupLabel,
  conflictType,          // teacher | student | blackout | ...
  conflictTypeLabel,
  conflictContent,       // 检测返回的文案，多条换行
  slotId, taskId,
  ignoredLikely: true    // 可选：类型属于可强制继续
}
```

只用于展示，不写回 `task` / `slot`。

## 13. 验收标准

1. 「排课表时间」下第四项为「课表冲突查询」，page-id `schedule-time-conflict`。  
2. 教室侧「场地冲突查询」菜单、页面、结果与改前一致。  
3. 只出现时间侧冲突类型；无教室时间 / 座位数 / 场地类型。  
4. 冲突类型下拉可过滤；「全部」出所有类型。  
5. 已排且命中不排课 / 教师排课时间 / 先修等可忽略类型的节次能查出（覆盖忽略插入）。  
6. 师生硬冲突若数据中存在也能查出。  
7. 日期、周次、星期联动正确；节次筛选覆盖联排。  
8. 同一冲突按重叠周分行，日期与周一致。  
9. 联排显示完整节次与起止时间。  
10. 本页无写回课表；无结果时不能导出空文件。  
11. 只测排时间入口：除本菜单外，按入学批次 / 教师 / 课程排行为不变。
