## 2. 建设目标与范围

### 2.1 目标

规范专业开课**任务安排层**：对计划已生效的教学班，分三步完成开课前期设置、课程班（合班 · Support）、师资安排（教师 · 授课确认 · 共同授课），满足门槛后批量**生效**，进入开课名单与下游排课/开课清单。

### 2.2 范围内

- 三步引导：① 开课前期设置 ② 课程班（合班 · Support）③ 师资安排
- 分组工作台：分组、学时投递、安排教师
- Support 管理、授课确认管理、共同授课设置
- 任务批量生效 / 撤回 / 退回计划
- 与计划层独立的双层状态（计划已生效 + 任务草稿/已生效/回退）

### 2.3 非目标（不在本菜单）

- 不含计划层「生成开课任务」
- 不含名单维护本体（生效后由开课名单承担）
- 不含通识选修开课安排合页细节
- 样式一宽表仅作历史对照，产品主路径以样式二为准

## 3. 用户角色与使用场景

| 角色 | 场景 | 目标 |
|------|------|------|
| 教务 | 计划生效后 | 完成三步安排并推动任务生效 |
| 学院 | 步骤 3 | 安排教师、分组、学时投递 |
| 教师 | 授课确认（教师端 / 开课清单侧栏） | 确认授课安排 |
| 教务 | 授课未齐或需改安排 | 撤回或退回计划 |

## 4. 在整体业务链路中的位置

```text
开课计划（已生效）→ 【开课安排】→ 任务生效 → 开课名单
                         │
                    授课确认（齐套为生效门槛）
                         │
                    开课清单 / 排课 / 选课（下游）
```

操作流程图明确：**未完成授课确认不可进入开课名单**；「提交到开课名单」语义对齐为不可跳过确认而进入名单维护阶段。

## 5. 主业务流程

1. 列表仅展示计划已生效的教学班；按步骤 1→2→3 依次完善信息。
2. **步骤 1**：设置课程基础信息与教室（可接特殊课程设置默认）。
3. **步骤 2**：合班（计划已生效且任务未生效时可合）、维护 Support 学院。
4. **步骤 3**：进入分组工作台安排教师与学时；完成授课确认（全部教师已确认，含代确认）。
5. 满足生效门槛后工具栏「生效」→ 任务已生效 → 开课名单可见、可维护。
6. 「撤回」：任务回草稿，保留合班/分组/教师，**重置学生小组分配**；已有排课则禁止撤回。
7. 「退回」：计划变回退，清空分组/教师，**保留合班**（须手动拆班）；已生效任务不可退回。

**关键约束：任务生效前须授课确认齐套**——无教师或存在未确认教师时硬拦截生效；零学时班亦不豁免教师安排完整性要求（以实现为准）。

## 6. 职责边界

| 职责 | 说明 |
|------|------|
| 负责 | 任务安排三步、分组/教师/Support、授课确认进度、任务生效/撤回/退回 |
| 不负责 | 计划生成、名单入组维护、选课应用生成开放选课名单 |
| 与他模块交接点 | 计划已生效 ← 开课计划；任务已生效 → 开课名单；授课确认 ↔ 教师端/开课清单 |
