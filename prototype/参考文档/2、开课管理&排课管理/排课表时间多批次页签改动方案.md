# 排课表时间 · 排课界面多批次页签改动方案

> 文档性质：代码改动方案（需求整理 · 设计）  
> 适用范围：排课管理 → **排课表时间** → 排课界面（`#page-schedule-time-detail`）  
> 状态：待评审 / 待实现  
> 关联现状：详情页面包屑 + 全局单例 `scheduleBatchDetailContext`；列表「排课」可走浏览器新页签深链

---

## 1. 背景与目标

### 1.1 现状问题

排时间侧排课界面（`schedule-time-detail`）当前为**单会话**：

| 点 | 现状 |
|----|------|
| 导航 | 顶栏面包屑：`排课表时间 / 按入学批次排 / {专业·批次}` |
| 当前对象 | 工具栏「当前批次」下拉 `#schedule-scope-select` |
| 切换批次 | `onScheduleScopeSwitch` → `openScheduleBatchDetail` → **整页上下文重置**，上一批次会话丢失 |
| 状态模型 | `scheduleBatchDetailContext`、选中课程、草稿、左侧 tab 等均为**全局单例** |
| 多开方式 | 列表「排课」可 `target=_blank` 开浏览器新页签，但页内仍无法并行保留多个批次工作区 |

排课员常需对照多个入学批次同时操作；单会话切换会打断未完成排课状态。

### 1.2 目标

1. **取消**排时间侧排课界面面包屑导航。  
2. **改为**页签（Tab）工作台：页签名称显示**当前批次**（专业 · 入学批次）。  
3. 在「当前批次」下拉中**选择尚未打开的批次**时：**新增页签**并打开该批次排课界面，不覆盖已有页签。  
4. 页签之间可切换，各自保留对应批次的排课界面状态。  
5. **支持同时打开多个批次页签**，在同一详情页内并行排课操作。

### 1.3 非目标（本期不做）

| 项 | 说明 |
|----|------|
| 排课表教室侧多页签 | 教室详情页结构类似，可复用同一模式，但本期仅改时间侧 |
| 按教师 / 按课程多页签 | 需求表述以「批次」为准；教师/课程入口可先保持单会话，或复用同一会话框架但页签文案改对象名（见 §5.3） |
| 跨浏览器页签的任务实时同步 | `SCHEDULE_TASK_STORE` 仍为单文档内存仓；浏览器多窗口互不同步问题本期不解决 |
| 替换列表页入口交互 | 列表「排课」仍可进详情；进详情时打开/激活对应批次页签即可 |

## 3. 目标交互（改后）

### 3.1 顶栏结构

```
┌─────────────────────────────────────────────────────────────────┐
│ [页签条：批次A ×] [批次B ×] [批次C ×]     …          [返回]   │
└─────────────────────────────────────────────────────────────────┘
│ 左侧课程列表 + 右侧课表（显示「当前激活页签」对应批次）          │
│ 工具栏：当前批次 [下拉]  …                                      │
└─────────────────────────────────────────────────────────────────┘
```

- **取消面包屑**整块 DOM（根 / 中段 / 标题三级）。  
- **保留「返回」**：行为不变，回到来源列表（`getScheduleDetailBackPage`）。  
- **页签条**占原面包屑区域；页签过多时横向滚动，不换行撑高。

### 3.2 页签命名

| 作用域类型 | 页签标题（建议） |
|------------|------------------|
| 入学批次（本期主场景） | `{专业中文名} · {入学批次展示}`，与现 `getScheduleDetailTitle()` 一致 |
| 超长标题 | 中间省略，`title` 属性挂完整文案 |

页签结构建议：

```html
<button class="schedule-workspace-tab is-active" data-scope-key="PROG|202409">
  <span class="schedule-workspace-tab-label">会计学 · 2024/09</span>
  <span class="schedule-workspace-tab-close" title="关闭">×</span>
</button>
```

### 3.3 打开 / 切换 / 关闭规则

| 触发 | 行为 |
|------|------|
| 列表点击「排课」（同页进入） | 若该批次页签已存在 → **激活**；否则 **新建**页签并激活 |
| 列表「排课」浏览器新页签深链 | 维持现有深链；新文档内仅打开该批次一个页签（不强制带历史页签） |
| 「当前批次」下拉选中**已打开**批次 | **切换**到对应页签（不新建、不重置该页签 UI 状态） |
| 「当前批次」下拉选中**未打开**批次 | **新增页签**并激活；原页签会话保留在后台 |
| 点击页签 | 激活该批次，刷新详情主体为该会话 |
| 点击页签 × | 关闭该页签；若关闭的是当前页签，激活相邻页签；若关闭后无页签，执行与「返回」相同逻辑（回列表） |
| 关闭页签时有未保存草稿 / dirty | 二次确认（文案对齐现有未保存提示，若无则新增轻量 confirm） |

### 3.4 「当前批次」下拉与页签的关系

- 下拉**数据源不变**（仍 `buildScheduleBatchSummaries()`）。  
- 下拉**选中值**始终等于**当前激活页签**的 `scopeKey`。  
- **语义变更**：由「替换唯一上下文」改为「打开或切换页签」。  
- 不在下拉中删除已打开批次；关闭只能通过页签 ×。

## 4. 技术方案

### 4.1 核心思路

将「单一全局详情状态」改为：

```
SCHEDULE_TASK_STORE          ← 继续全局共享（任务数据唯一源）
scheduleWorkspaceTabs[]      ← 打开的页签列表（有序）
scheduleWorkspaceActiveKey   ← 当前激活 scopeKey
sessions: Map<scopeKey, SessionState>  ← 每页签独立 UI 会话
```

渲染时：以激活会话 hydrate 到现有 DOM（仍只用一份详情 DOM），避免复制整页导致重复 id。

### 4.2 scopeKey 约定

复用现有键：

```js
// 批次
`${programmeKey}|${intake}`   // 与 getScheduleScopeSwitchInfo().current 一致
```

辅助函数建议：

| 函数 | 作用 |
|------|------|
| `getScheduleWorkspaceScopeKey(ctx)` | 由 context 生成 key |
| `getScheduleWorkspaceTabLabel(ctx)` | 页签显示名（复用/抽取 `getScheduleDetailTitle`） |
| `ensureScheduleWorkspaceSession(ctx)` | 无则建会话，有则返回 |
| `activateScheduleWorkspaceTab(scopeKey)` | 切换激活并 `renderScheduleDetailPage` |
| `openScheduleWorkspaceTab(ctx, { activate })` | 打开或复用页签 |
| `closeScheduleWorkspaceTab(scopeKey)` | 关闭 + 处理激活迁移 |
| `renderScheduleWorkspaceTabs()` | 渲染页签条 |

### 4.3 SessionState 建议字段

从现有全局变量中拆出（至少）：

```js
{
  ctx: { type:'batch', programmeKey, intake, phase:'time' },
  activeTaskId,
  activeHourType,
  courseExplicitlyCleared,
  activeFromCourseList,
  selectedIds: Set,          // 课程勾选
  selectedSlotIds: Set,      // 节次多选
  draftForTaskId,
  courseTab,                 // all / pending / done
  courseSearchQuery,
  courseSearchField,
  dirty,
  savedAt,
  // 可视配置若需按批次记忆，再纳入；否则可继续全局共享
}
```

**仍建议全局共享（不进 Session）：**

- `SCHEDULE_TASK_STORE`（改课结果各页签应立即可见）  
- 学期节次、冲突检测规则、房间元数据等基础配置  

**切换页签时：**

1. `persistActiveScheduleWorkspaceSession()`：把当前全局 UI 状态写回 Map。  
2. `hydrateScheduleWorkspaceSession(key)`：从 Map 灌回全局变量 + 更新 `scheduleBatchDetailContext`。  
3. `renderScheduleDetailPage()`（或抽取的 `renderScheduleDetailBody()`）。

> 说明：为降低改造面，第一期可采用「Session ↔ 现有全局变量」进出栈适配，而不是一次性把所有 `render*` 改为传 session 参数。第二期再逐步参数化。

### 4.4 与 `openScheduleBatchDetail` / `onScheduleScopeSwitch` 的改造

#### （1）`onScheduleScopeSwitch(value)`（关键变更）

```
改前：openScheduleBatchDetail → reset 全局 → 覆盖
改后：
  key = value
  if tabs 已含 key → activateScheduleWorkspaceTab(key)
  else → openScheduleWorkspaceTab(parsedCtx)  // 新建 + 激活，不销毁其它会话
```

新建会话时才 `reset` **该会话**初始状态，不得 `reset` 其它页签会话。

#### （2）`openScheduleBatchDetail(programmeKey, intake)`

列表 / 深链入口统一走：

```
openScheduleWorkspaceTab({ type:'batch', programmeKey, intake, phase:'time' })
goPage('schedule-time-detail')   // 若尚未在详情页
```

不再无条件 `resetScheduleDetailState()` 清空全部工作台。

#### （3）`backFromScheduleDetailPage`

建议两档策略（评审二选一，推荐 A）：

| 方案 | 行为 |
|------|------|
| **A（推荐）** | 返回列表时**清空页签栈**（离开工作台）；再次进入重新开页签 |
| B | 返回列表但**保留页签栈**（再次进详情仍在）；需处理从教师/课程入口进入时的栈冲突 |

本期推荐 **A**，实现简单、语义清晰。

### 4.5 DOM / CSS 改动

#### HTML（`#page-schedule-time-detail` 页头）

```html
<!-- 删除 .breadcrumb 整块 -->
<div class="page-header compact schedule-detail-header">
  <div class="schedule-workspace-tabs" id="schedule-workspace-tabs" role="tablist"></div>
  <div class="page-header-actions">
    <button class="btn btn-ghost btn-sm" type="button" onclick="backFromScheduleDetailPage()">返回</button>
  </div>
</div>
```

#### CSS（新建，建议放在排课详情样式区）

- `.schedule-workspace-tabs`：横向 flex，overflow-x auto，与页头同高  
- `.schedule-workspace-tab`：类浏览器页签外观，贴合现有蓝系（避免另起紫色/圆角胶囊风）  
- `.is-active`：底边强调色 + 背景略亮  
- `.schedule-workspace-tab-close`：hover 显示，阻止冒泡  
- dirty 可选：页签 label 前加点 `·` 或 `*`  

不复用 `.schedule-detail-tab`（左侧课程筛选 tab，语义不同）。

### 4.6 JS 模块落点（建议）

集中在 `prototype/app.js` 排课详情区附近（`openScheduleDetailScope` / scope switcher 前后），新增「工作台页签」函数块，避免散落。

需改动的既有函数（清单）：

| 函数 | 改动要点 |
|------|----------|
| `renderScheduleDetailPage` | 渲染前 hydrate；渲染后 `renderScheduleWorkspaceTabs`；去掉面包屑赋值 |
| `onScheduleScopeSwitch` | 打开/切换页签，禁止整栈 reset |
| `openScheduleDetailScope` / `openScheduleBatchDetail` | 接入工作台 |
| `backFromScheduleDetailPage` | 按 §4.4 清空或保留栈 |
| `resetScheduleDetailState` | 拆为「会话级 reset」与「工作台级 clear」 |
| `wireScheduleDetailBackControls` | 去掉面包屑绑定 |
| `tryOpenScheduleDetailFromUrl` | 打开单页签即可 |

### 4.7 与浏览器新页签深链的关系

| 场景 | 策略 |
|------|------|
| 同文档内多批次 | **页内工作台页签**（本方案） |
| 列表「排课」`_blank` | 保持；每个浏览器页签内独立工作台，互不同步任务（现状限制，文档标明） |
| 是否取消 `_blank` | **本期不取消**；若产品希望「只在页内多开」，可另开需求改为同页 `openScheduleWorkspaceTab` |

## 6. 实施步骤（建议分期）

### Phase 1 — 壳与导航（可见改动）

1. 去掉时间侧详情面包屑 HTML/JS。  
2. 增加页签条 DOM + 样式 + `renderScheduleWorkspaceTabs`。  
3. 进入详情 / 下拉切换：打开或激活页签（可先**不**做完整 Session 隔离，仅切换 `scheduleBatchDetailContext` 并重渲，验证交互）。  

### Phase 2 — 会话隔离（正确性）

1. 引入 `Map<scopeKey, SessionState>` 与 persist/hydrate。  
2. 改造 `onScheduleScopeSwitch`、`openScheduleBatchDetail`，禁止误清其它会话。  
3. 关闭页签、返回清空栈、dirty 确认。  

### Phase 3 — 打磨

1. 超多页签滚动、激活页签滚入可视区。  
2. 与列表深链、沉浸式隐藏侧栏回归。  
3. （可选）教师/课程维度一并接入。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 全局变量漏拆导致页签串状态 | 勾选/草稿串到其它批次 | Session 字段对照表 + 切换前后单测清单 |
| 任务仓共享导致 A 页签改课影响 B 课表 | 预期行为（应同步） | 文档写明；切换回来时必须重渲课表 |
| 固定 DOM id 无法多实例并行渲染 | 不能同时「真·双课表」上屏 | 采用单 DOM + 会话切换（可接受） |
| 与 `_blank` 双模型并存 | 用户困惑 | 列表提示保持「新浏览器页签」；页内下拉明确「打开页签」 |
| 关闭页签丢未保存操作 | 数据丢失体感 | dirty 确认；必要时关闭前 `persist` |
| `goPage` 离开详情 | 页签栈是否保留 | 本期采用离开即清空（方案 A） |

## 9. 验收标准（产品）

1. 排时间侧排课界面**不再显示面包屑**。  
2. 顶栏以**批次页签**展示已打开对象，名称可读。  
3. 通过「当前批次」选择新批次时**新增页签**，不覆盖旧页签。  
4. 多页签可切换，且各自可继续排课。  
5. 支持同时打开 ≥ 3 个批次页签完成基本排课操作无串数据（UI 状态不串；任务数据全局一致）。
