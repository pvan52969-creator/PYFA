## 文档概述

### 1.1 文档目的

本文档为厦大马来分校教务系统「培养方案管理（Curriculum Management）」模块提供标准化需求输入，描述已完成的可交互原型功能、字段、业务规则与数据流转关系，可直接用于需求评审、后续开发与测试用例编写。

### 1.2 开发背景

- **开发模式：** 边分析边迭代，分模块生成可交互原型  
- **目标用户：** 学院 Programme Office、教务处 Academic Affairs、Senate 审批人员、培养方案制定人员  
- **覆盖范围：** 本科生培养方案版本制定、审批、变更、执行计划及数据统计  
- **原型路径：** `prototype/`（纯前端内存数据，无后端 API）

### 1.3 文档说明

- 本文档依据现有原型逆向整理，与模板格式对齐  
- 已确认的需求标记为 **「已确认」**；导出模板等待补充的标记为 **「待确认」**  
- 原型中 `alert('原型')` 类占位功能在备注中单独说明  
- 入学批次编码规则：每年 **02 → 04 → 09**（如 202509 → 202602 → 202604 → 202609）

### 2.2 培养方案管理 — 系统需求

#### 2.2.1 方案版本（英文名称：Programme Version）（需求确认状态：已确认）

**模块介绍：** 管理各专业不同入学批次的培养方案版本全生命周期，包括版本制定、三级审批、只读查询、版本导出及批次链衔接；是执行计划与方案变更的上游数据源。

##### 2.2.1.1 方案版本管理（英文名称：Programme Version Management）（需求确认状态：已确认）

**菜单介绍**

| 项目 | 内容 |
|------|------|
| 菜单内容简介 | 用于管理各专业培养方案版本的创建、编辑、删除、提交审批、批量导出及版本引用查询。同一专业可存在多个按批次链衔接的版本；支持按专业、版本过滤查询；列表展示审批状态、批次区间、引用情况等核心信息。 |

**页面展示字段信息**

勾选框、培养方案版本（Programme Version Name）、审批状态（Status）、专业代码（Major Code）、学制（Duration）、版本（Version）、开始批次（Start Intake）、截止批次（End Intake）、授予学位（Degree Awarded）、版本引用情况（Reference Count）、操作（Actions）。

**支持查询检索的字段信息**

专业（Major）、版本（Version）。

**数据前后流转关系**

1. **关系说明：** 用户在列表页发起新增/编辑/删除/提交/导出操作；新增版本时选择专业与开始批次，系统校验批次链规则后创建草稿版本并进入三 TAB 编辑视图；提交审批时校验必修分类最低学分后写入审批队列；审批通过后版本 status 变为 approved 并自动回填上一版本截止批次；删除仅允许草稿/已驳回且无下游强引用；导出请求汇总所选版本全量方案内容生成文件（**导出模板待确认**）；版本内容作为执行计划生成与方案变更的目标数据源。  
2. **前置条件：** 已维护专业主数据（专业代码、学制、授予学位）；已维护入学批次代码集（02/04/09）；课程库（Course Catalog）可用于 TAB2 选课。  
3. **下游输出：** 已通过版本 → 执行计划生成、方案变更申请、版本查询、Bloom/Alignment 统计；版本引用数关联 EXEC_PLANS 执行计划列表。

**业务流关系（操作流程）**

操作流程：进入【方案版本管理】→ 过滤/查询 → 新增版本（选专业、开始批次）→ 进入制定（TAB1 分类 → TAB2 课程 → TAB3 进程表）→ 保存 → 提交审批 → 进入【版本审批】三级流程 → 通过后可在【版本查询】只读查看、在【批次执行计划】生成执行计划、在【方案变更申请】发起变更。

**批次链规则（业务校验）**

- 同专业多版本区间不重合：上一版本截止批次 = 下一版本开始批次的前一批次（如 2025/09 → 2025/04）  
- 当前有效版本：status=approved 且 endBatch 为空  
- 仅 approved 版本自动回填 endBatch；draft/pending/rejected 的 endBatch 为空  
- 新版本 startBatch ≥ 当前有效版本的下一批次

##### 2.2.1.2 版本审批（英文名称：Programme Version Approval）（需求确认状态：已确认）

**菜单介绍**

| 项目 | 内容 |
|------|------|
| 菜单内容简介 | 按审批节点统一管理培养方案版本的三级审批待办、进行中与历史记录；支持单条 Review、批量 Review、查看 Approval Log 及只读 View 方案内容。 |

**页面展示字段信息**

勾选框（仅 Pending 可审项）、培养方案（Programme）、Status、Stage、专业（Major）、开始批次（Start Intake）、总学分（Total Credits）、提交人（Submitter）、提交时间（Submit Time）、操作（Actions）。

**支持查询检索的字段信息**

Tab 分桶：Pending / In Progress / History（Pending 显示待办数量 badge）。

**数据前后流转关系**

1. **关系说明：** 版本提交审批后写入 APPROVAL_QUEUE；各级审批人 Review 后更新 stages 状态；末级 Approve 后版本 status→approved 并 syncVersionEndBatches；Reject/Update Required 后版本 status→rejected 可退回修改。  
2. **前置条件：** 版本已提交且 status=pending。  
3. **下游输出：** 审批通过 → 版本可供查询、执行计划生成、变更申请；审批日志供 Audit。

**业务流关系（操作流程）**

操作流程：进入【版本审批】→ Pending Tab 勾选待办 → Review → 填写审批意见 → Approve / Reject / Update Required → 逐级流转至 Senate 终审。

**审批节点**

| Level | Role | 中文标签 |
|-------|------|---------|
| 1 | Programme Office | 一级审批 · Programme Office |
| 2 | Academic Affairs | 二级审批 · Academic Affairs |
| 3 | Senate | 三级审批 · Senate |

**决策类型：** Approve（进下一级/终审通过）、Reject（驳回）、Update Required（退回修改，status→rejected）。

**菜单功能清单**

a. **功能说明：**
- **描述：** 审批人对当前节点待办进行审批决策。  
- **业务的事件交互：** Pending 行点击 Review → 弹窗展示当前节点、审批意见输入 → Approve / Reject / Update Required。  
- **备注信息：** View 为只读查看方案三 TAB；Approval Log 展示各级审批记录。

**2、功能按钮 — Batch Review（英文名称：Batch Review）**

a. **功能说明：**

##### 2.2.2.1 方案变更申请（英文名称：Change Application）（需求确认状态：已确认）

**菜单介绍**

##### 2.2.3.1 批次执行计划（英文名称：Programme Intake Execution Plan）（需求确认状态：已确认）

**菜单介绍**

| 项目 | 内容 |
|------|------|
| 菜单内容简介 | 管理各专业入学批次的培养方案执行计划；从 approved 版本自动匹配并复制内容；支持生成、编辑、提交、撤回、删除及批量操作。 |

**页面展示字段信息**

勾选框、专业代码、专业、专业批次、学院（School）、入学批次、开课状态、是否提交、操作。

**支持查询检索的字段信息**

学院、专业、批次、状态（草稿/已发布）（**原型 UI 占位，逻辑待接**）。

**数据前后流转关系**

1. **关系说明：** 选专业 + 入学批次 → 按 `versionCoversBatch` 自动匹配 approved 版本 → 复制到 EXEC_CONTENT_STORE → 生成 draft 执行计划 → 提交后 isLocked=true → 可开课 isOffering=true。  
2. **前置条件：** 存在覆盖该入学批次的 approved 版本；同专业同入学批次不可重复生成。  
3. **下游输出：** 执行计划独立副本，不受后续版本变更影响；版本引用数统计来源。

**生成执行计划 — 字段信息表**

| 序号 | 字段中文名称 | 英文名称 | 字段类型 | 必填 | 校验规则 | 备注 |
|------|------------|---------|---------|------|---------|------|
| 1 | 专业 | Major | 下拉框 | 是 | — | — |
| 2 | 入学批次 | Intake Batch | 下拉框 | 是 | 02/04/09 | — |
| 3 | 匹配培养方案版本 | Matched Programme Version | 只读 | 是 | 自动匹配 | 锁定不可改 |

**业务规则**

- 编辑：`!isLocked && !isOffering`  
- 删除：未提交且未开课  
- 撤回：`isLocked && !isOffering`  
- 已开课：须先删除开课任务方可撤回/删除  
- 编辑界面复用 `page-version-edit`，显示执行计划副本说明横幅；课号/课名不可改

**菜单功能清单**

**1、功能按钮 — 生成执行计划（英文名称：Generate Plan）**  
弹窗 `modal-gen-exec` → 「生成并编辑」进入三 TAB。

**2、功能按钮 — 提交 / 撤回 / 删除（批量）**  
弹窗：`modal-exec-lock`、`modal-exec-unlock`、`modal-exec-delete`、`modal-exec-notice`。
