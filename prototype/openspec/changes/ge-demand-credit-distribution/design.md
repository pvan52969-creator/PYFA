## Context

See proposal.md — Why。现有「开课需求」上段已有文/商/理人数摘要与按学院明细表（演示数据，`ensureGeOfferingDemand`）。本期在同一卡片加第二 Tab，不改下段学院配额。

## Goals / Non-Goals

**Goals:**

- Tab 切换：`按学院明细` / `GE学分分布预估`
- 第二 Tab：文、商、理三卡并排（总人数、2 学分人次、3 学分人次）
- 纯前端按确认规则拆分；假数据标准学分主造 4～7
- Tab B 三卡人数之和 = 现有文商理三卡人数之和；刷新共用

**Non-Goals:**

- 本期不做第二张明细表（批次/学院展开）
- 不接真实执行计划最高学分接口（正式环境另议）
- 不改学院配额保存逻辑、不改选课名单生成

## Decisions

1. **假数据挂在批次上，不按学院直接造学分**  
   - 选择：为参与需求的专业批次写死本学期 `standardCredits`（4～7 为主），按批次算人次再按 `PROGRAMME_GE_STREAM_MAP` 归入文/商/理。  
   - 理由：与正式「批次 × 学期最高学分」一致，且便于对齐「三卡人数之和」——剔除标准学分 < 2 的批次时，须同步从人数侧剔除或保证假数据无人 < 2。  
   - 备选：只按文商理总人数各赋一个学分档——更简单，但无法演示多批次累加，否决。

2. **人数一致性策略**  
   - 选择：假数据中所有计入需求的批次标准学分均 ≥ 2（默认 4～7），故无需剔除；若后续演示加 &lt; 2 批次，计算层剔除其人次且不计入该流总人数，并保证摘要文商理与 Tab B 同源。  
   - 备选：Tab B 独立造人数——易漂，否决。

3. **拆分算法集中成纯函数**  
   - 输入：`standardCredits`、`headcount` → 输出 `{ seats2, seats3 }`  
   - 固定档 2/3/4/5/7；50/50 档 6/8/9/10/11；奇数规则一。  
   - 便于单测/手测验算示例。

4. **UI 结构**  
   - 卡片头下增加 Tab；摘要三卡可保留在两 Tab 共用或仅在学院 Tab 显示——**决定：摘要区始终显示现有文商理人数；Tab B 另做三张「学分分布」卡，避免与摘要抢同一套 UI。**  
   - Tab 默认：`按学院明细`。

## Risks / Trade-offs

- [假数据与正式学分脱节] → Mitigation：界面标注「演示数据」；design/spec 写明正式取执行计划最高学分。  
- [偶数期望值出现 .5 人次] → Mitigation：产品已接受；展示可保留一位小数或四舍五入为整数——**本期展示用可整除时的整数，期望值计算若为 x.5 则展示一位小数（如 75、50、125）**；若产品要求一律整数再改。  
- [用户误以为 Tab B 改配额] → Mitigation：文案标明「预估人次」，不提供编辑。

## Migration Plan

原型增量即可；无数据迁移。回滚删除 Tab 与相关函数即可。
