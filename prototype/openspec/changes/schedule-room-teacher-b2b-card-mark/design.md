# Design

## Context

See proposal.md - Why。现状要点：

- 排教室左侧卡由 `buildScheduleRoomMergedSlotCards` 生成；「节次类型」`scheduleRoomPeriodGrainMode` 控制大节次合并 / 小节次拆分（仅影响侧栏，不影响右侧 1h 一格）。
- 一键导入已有教师邻接与就近打分（`scheduleRoomSlotsAreAdjacentPeriods`、`scheduleTasksShareTeacher`、`findScheduleRoomOneClickTeacherNearRoom`），但**同课连堂也可作锚点**；本标记强调**课号或课组不一致**，需独立判定函数，勿直接复用「有锚点教室」结果当标记条件。
- 侧栏课号行已有类型徽标（如 Major Core）与状态图标；共同授课曾用卡间锁扣后已弃用，产品要求关系尽量用卡内字段表达——B2B 是跨卡时间关系，适合轻量徽标而非再引入锁扣环。

## Goals / Non-Goals

**Goals:**

- 在卡片构建或列表渲染前，按当前粒度对卡片两两（同星期）做教师 B2B 邻接标注。
- 视觉上让排课员扫左侧列表即可看到跨课连堂边界；切换大/小节次后标记正确搬家。
- 左侧列表：**B2B 连通链成组紧挨**，组内与组间再按时间，便于对照徽标；多条并行 B2B 不得被纯时间序拆散。
- 实现隔离在教室侧分支，遵守时间/教室页独立性。

**Non-Goals:**

- 不改一键导入挑教室算法与确认弹窗文案（老师 B2B 规则条已隐藏可保持）。
- 不做学生 B2B 卡面标记。
- 不在右侧课表格内画 B2B，不改排时间侧栏。
- 不恢复「人数多优先」作为侧栏主序。
- 不做「纯时间序、指望 B2B 自然相邻」（并行链场景会失败）。

## Decisions

### 1. 判定单位：展示卡，不是原始 slot

- **选择**：用合并/拆分后的 `card.weekday / periodFrom / periodTo / teacherKey / code / unitKey(课程组)` 做邻接。
- **理由**：产品示例明确绑在「大节次整体卡」vs「小节次边界小时」上。
- **备选**：按原始 slot 小时展开再映射回卡——更准但实现重，且与粒度开关重复。

邻接定义：`same weekday` + `weeks overlap` + `a.periodTo + 1 === b.periodFrom`（有向贴接；无向时两侧都标）。

课号/课组不一致：规范化课号不同 **或** `unitKey`（含 `@@groupId`）不同。同课同组不标。

教师相同（已定稿）：**有共同教师即算**——两侧卡片 entries 的任务存在任一共同教师（对齐 `scheduleTasksShareTeacher` / 工号或姓名交集）；不要求教师集合完全一致。

### 2. 标记数据结构

在卡上挂只读字段，例如：

```text
teacherB2b: {
  prev: { mergeId, codeLabel, periodFrom, periodTo } | null,
  next: { mergeId, codeLabel, periodFrom, periodTo } | null
}
```

`prev` / `next` 任一非空即显示标记。连续链中间卡可同时有 prev+next。

在 `buildScheduleRoomMergedSlotCards` 末尾、写入 `scheduleRoomMergedCardsById` 前跑一遍 `annotateScheduleRoomTeacherB2bMarks(cards)`。

### 3. 视觉方案（已定稿：方案 A）

| 方案 | 形态 | 结论 |
|------|------|------|
| **A. 课号行小徽标** | 课号旁 pill：`B2B`，`title`=`Back to back（教师）· …` | **采用**（产品确认） |
| B. 独立字段行 | 字段写全称 | 不采用（卡片过高） |
| C. 卡间竖向连接条 | 两卡之间衔接条 | 不采用（列表非时间序易误导） |
| D. 仅色点无文字 | 圆点 | 不采用（需图例） |

落地约定：

- 徽标可见文案带伙伴课号：`B2B→MEC920` / `MEC914→B2B`（中间卡 `B2B A↔C`）；完整说明仍在 title。
- 列表相邻且互为上下接时，卡间接缝画 **B2B 衔接条** + 左缘色条，强调「这两张之间」的关系。
- **不**恢复共同授课卡间锁扣（那是另一类关系）。

示意（大节次）：

```text
+----------------------------------+
| MEC901  [MC] [B2B]               |
| 教师 A · 9:00-11:00              |
+----------------------------------+
| MEC902  [MC] [B2B]               |
| 教师 A · 11:00-12:00             |
+----------------------------------+
```

小节次时仅边界小时卡带 `[B2B]`。

### 4. 侧栏排序：B2B 成组优先，时间作大序（已定稿）

现状：`sortScheduleRoomMergedCardsPreferSharedTeaching` 以**人数多优先**再时间——会打散 B2B。

产品澄清（并行 B2B）：

```text
错误（纯时间）：A(9-10), C(9-10), B(10-11), D(10-11)
正确（先成组）：A(9-10), B(10-11),  C(9-10), D(10-11)
                 \____链1____/      \____链2____/
```

即：A↔B、C↔D 各是一条教师 B2B 链时，**每条链内部紧挨**；不能因为「都先排 9–10 再排 10–11」把两条链交叉拆开。

**选择**：

1. 先按教师 B2B 邻接关系求**连通分量**（链/组）；单卡无 B2B 则各自一组。
2. **组内**按时间：`periodFrom` → `periodTo` → 课号。
3. **组间**按该组最早时间（min periodFrom，再 min periodTo，再代表课号）排序——时间是「大的优先」，但服从成组约束。
4. **不再**以人数作为主序（旧比较函数注释弃用原因）。
5. 同时段共同授课伙伴：可并入同组或作为组内次级聚类；不得拆开已有教师 B2B 链。
6. annotate 的 `prev/next` 与成组后的列表相邻关系应对齐，便于 title 与扫读一致。

**备选（不采用）**：

- 纯时间序——并行 B2B 会变成 A、C、B、D。
- 人数优先再插 B2B——与连堂阅读心智不符。

### 5. 与一键导入 B2B 的关系

- **共用**：星期/周次/节次贴接、同教师工具函数可抽薄封装。
- **不共用结果**：导入锚点允许同课；卡面标记要求课号或课组不一致。
- 确认弹窗是否恢复「老师 B2B」条文案：本设计不依赖，保持现状（已隐藏）。

### 6. 性能

侧栏卡数量通常为当前星期作用域内数十级。时间排序 + 同 weekday 线性扫邻接即可 O(n log n)。

## Risks / Trade-offs

- [大班不再置顶] → 产品接受；一键导入内部仍可按人数优先处理任务队列。
- [并行 B2B 交叉] → 用连通分量成组，避免纯时间序拆链。
- [多教师课] → **已定**：有共同教师即算。
- [周次部分重叠] → 有交集即标。
- [徽标拥挤] → 优先保留 B2B + 类型徽标。

## Migration Plan

- 纯前端原型：发布即生效；无数据迁移。
- 回滚：去掉 annotate + 徽标 HTML/CSS 即可，不影响派教室数据。

## Open Questions

- （已关闭）徽标短标 → **`B2B`**；教师判定 → **有共同教师即算**。
- 是否需要点击 B2B 滚动/高亮伙伴卡？本版不做，可作后续增强。
