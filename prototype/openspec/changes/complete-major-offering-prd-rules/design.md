## Context

See proposal.md — Why。基线文档为《开课计划》《开课安排》**20260804V2**（位于各自版本文件夹）；行为源以可交互原型 `app.js` 为准。曾短暂产出的 V3 已删除；本 change 相对 V2 一次补齐全部遗漏与冲突，产出 V4 + **V2→V4** 变更说明。

## Goals / Non-Goals

**Goals:**

- 文档追齐原型；V4 可直接作开发验收。
- 一版一文件夹；变更说明对照 V2→V4（不经 V3）。
- 计划 / 安排交叉引用一致。

**Non-Goals:**

- 不恢复 V3；不重构合班/生效代码；不扩展通识/校选。

## Decisions

### D1 — 冲突项以原型为准

| 冲突 | 定稿 |
|------|------|
| 退回计划时合班 | **保留合班**，手动拆 |
| 是否排考默认 | **是** |
| 开放选课计划总人数 | **可编辑且必填**（老生/新生仍只读） |

### D2 — 相对 V2 增量写入 V4

在 V2 正文上合并：学时↔排场地/考勤、保存校验、人数三口径、合班副作用、生效矩阵、退回/撤回总表等；状态图去掉「合班拆回」。

### D3 — 目录与脚本

```
…/开课计划/开课计划20260804V4/
  开课计划20260804V4.md|.docx
  开课计划20260804V2→20260804V4变更说明.md|.docx
```

脚本已支持版本子目录；`--version V4 --date 20260804`；变更说明 `--from V2 --to V4`。

### D4 — 原型改动阈值

默认零代码；仅原型自相矛盾时最小对齐。

## Risks / Trade-offs

- [Risk] 跳过 V3 使「学时规则」与「其余规则」合并进同一变更说明 → Mitigation：变更说明分行写清，类型用新增/修改/澄清。
- [Risk] 退回保留合班与旧记忆冲突 → Mitigation：变更说明前后对照醒目标注。

## Migration Plan

1. 基线已迁入版本文件夹；V3 已删。

3. 开发以 V4 为基线；V2 仅历史对照。
