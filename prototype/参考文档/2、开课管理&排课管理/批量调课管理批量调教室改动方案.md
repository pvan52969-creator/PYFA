# 批量调课管理 · 批量调教室改动方案

> 文档性质：代码改动方案（需求文档，供实现前对齐）  
> 适用范围：调课管理 → **批量调课管理** → 抽屉 **批量调教室**（`#adjustment-batch-tab-room` / `#modal-adjustment-batch`）  
> 关联代码：`prototype/index.html`、`prototype/app.js`、`prototype/styles.css`  
> 状态：**已按方案实现**  
> 对照已落地：`批量调课管理批量调时间改动方案.md`

## 0. 已确认口径

| 项 | 结论 |
| --- | --- |
| 改哪一侧 | **只改批量调教室 Tab**。批量调时间、列表查询区、排时间 / 排教室详情页、调课审批选教室不改 |
| 日期模式 | 源日期可切换 **按日期** / **按星期**；默认 **按日期**（保持现状） |
| 按星期字段 | 日期区内：起始周 + 截止周 + 星期（可搜索下拉多选）。**节次不放进日期区**，继续用现有「源节次」勾选格（与批量调时间一致） |
| 冲突列 | 明细表新增「冲突情况」；有冲突行浅黄高亮；列表顶部提示冲突条数 |
| 冲突口径 | 时间地点不变，只换教室 → **只做场地冲突**（目标教室在该日期/星期/节次/周次被占用，含明细行之间互撞）。不做教师/学生时间冲突 |
| 目标教室（表单） | 生成前仍必填，作为明细默认目标教室 |
| 目标教室（明细） | 改为选择器回显，点击可改该行教室；改后重算该批明细冲突 |
| 多选改教室 | 序号前列复选框；「清空调课明细」后增加「调教室」；勾选若干行后点「调教室」一次写入同一教室 |
| 仅查询冲突项 | 列表顶部复选，**默认不勾选**；勾选只展示 `conflict.hasConflict` 的行，不重新生成明细 |
| 提交 | 与批量调时间对齐：存在冲突明细时 **不能确定提交** |
| 教室弹窗 | 复用 `#modal-schedule-room-picker`，用独立 `scheduleRoomPickerMode` 分支，禁止改排时间 / 排教室详情交互 |

## 1. 改动目标

在批量调教室抽屉中补齐五块能力：

1. **源日期支持按星期选择**：切换后用起止周 + 星期多选展开为具体日期；节次仍用现有源节次。  
2. **调课明细增加冲突情况列**：高亮冲突行，列表顶部提示。  
3. **明细「目标教室」改为选择回显**：点击打开选教室弹窗，写回该行。  
4. **多选 + 调教室**：序号前复选；清空按钮后增加「调教室」，对勾选行批量改目标教室。  
5. **仅查询冲突项**：默认不勾；勾选后只显示冲突明细。

非目标（本期不做）：

- 不改 `#adjustment-batch-tab-time` 批量调时间表单、明细、提交（可 **复用** 其日期模式 / 多选下拉 / 冲突单元格样式，但函数里凡写死 `'time'` 的清明细逻辑必须按 `kind` 分支）。  
- 不改批量调课管理列表页查询条件。  
- 不改排课表时间 / 排课表教室详情页、右键菜单、锁定 / 待定。  
- 不改我的调课申请、调课申请管理、调课申请记录、调课申请审批选教室。  
- 不在按星期面板内再做一份节次选择。  
- 不把教室开放时间校验并入本期明细（审批选教室已有开放时间列，批量调教室本期不做）。

## 2. 现状摘要

### 2.1 入口与结构

| 项 | 现状 |
| --- | --- |
| 列表入口 | `#page-adjustment-batch` → `openAdjustmentBatchDrawer('room')` |
| 抽屉 | `#modal-adjustment-batch`，教室 Tab `#adjustment-batch-tab-room` |
| 状态 | `ADJUSTMENT_BATCH_STATE.room`：`dates` / `range` / `preview` / `sourceRoom` / `targetRoom` / `generatedKey`（**无** `dateMode` / `weekFrom` / `weekTo` / `weekdays`） |

教室侧表单当前只有：

```text
源日期（日历起止，仅按日期）
源节次（checkbox 多选）
源教室（选择教室按钮）
目标教室（选择教室按钮，生成时写入每一行）
[确定生成调课明细] [清空调课明细]
明细表：序号、课程编号、课程名称、教师、日期、节次、原教室、目标教室（纯文本）
原因类型 / 调整原因 / 附件
```

### 2.2 日期与命中

- 日期：`openAdjustmentBatchDatePicker('room')` → 选起止，展开为 `state.dates`。  
- 命中：`collectAdjustmentBatchHits('room')` 按 `dates × weekday × 源节次 × 源教室` 扫课表。  
- 生成：`previewAdjustmentBatch('room')` 给每行写入同一 `targetRoom`。  
- **不做冲突检测**，顶部 tip 仅「已生成 N 条」。

### 2.3 明细与提交

- 渲染：`renderAdjustmentBatchPreview('room')`，空表 `colspan=8`。  
- 「目标教室」列：`escapeHtml(r.targetRoom || '—')`，不可点。  
- 提交：`confirmAdjustmentBatch('room')` 把所有行的 `slot.room` 写成表单级 `ADJUSTMENT_BATCH_STATE.room.targetRoom`，**忽略行上可能被改过的 `r.targetRoom`**，也 **不拦冲突**。

### 2.4 可复用（必须按 kind 分支，禁止误清时间侧明细）

| 能力 | 位置 | 注意 |
| --- | --- | --- |
| 按日期 / 按星期切换 | `onAdjustmentBatchDateModeChange`、`syncAdjustmentBatchDateModeUi`、`fillAdjustmentBatchWeekSelects`、`expandAdjustmentBatchWeekdayDates` | 目前 `kind` 已参数化，但 `onChange` **写死** `clearAdjustmentBatchTimeGenerated()` + `renderAdjustmentBatchPreview('time')` |
| 星期可搜索多选 | `initAdjustmentBatchWeekdaySelect` → `renderAdjustmentBatchSsMulti` | `onChange` 同样写死清时间明细 |
| 选教室弹窗 | `#modal-schedule-room-picker`，`scheduleRoomPickerMode === 'batch'`（源/目标教室） | 时间侧行改教室用独立 mode `batchTimeRow`；教室侧行改 / 多选改需再加独立 mode，勿改 `batch` 表单源/目标逻辑 |
| 冲突单元格 / 高亮 | `renderAdjustmentBatchTimeConflictCell`、`.adj-batch-time-preview tr.is-conflict` | 教室侧可抽共用或复制一套 class 到 `.adj-batch-room-preview` |
| 时间侧冲突算法 | `checkAdjustmentBatchTimeRowConflict` | **不能直接套用**：其中 `sameAsOriginal` 在日期节次不变时直接视为无冲突，批量调教室恰恰是「同时段换教室」 |

## 3. 目标交互

### 3.1 表单（批量调教室）

```text
源日期
  [按日期 | 按星期]          ← 新增切换，默认按日期
  按日期：现有「选择起止日期」日历
  按星期：起始周、截止周、星期（可搜索多选）
  下方日期摘要（已展开的具体日期）保持

源节次（可多选）             ← 不变，按星期时同样必填

源教室                     ← 不变
目标教室                   ← 生成前必填，作为明细默认值；文案仍「选择教室」回显

[确定生成调课明细] [清空调课明细] [调教室]   ← 「调教室」在清空之后
[ ] 仅查询冲突项            ← 默认不勾，放列表顶部（与 tip 同一区域）
提示：有冲突时「已生成 N 条，其中 M 条存在冲突（浅黄高亮），无法提交」
明细表 …
```

切换日期模式时：

- 清空已展开日期与按星期字段，切到按星期时填充周次下拉并初始化星期多选。  
- **只清教室侧**已生成明细（`clearAdjustmentBatchRoomPreview` 同类逻辑），不要动批量调时间 preview。

按星期校验（对齐 `validateAdjustmentBatchWeekdaySide`）：

- 未选起止周 / 起始晚于截止 / 未选星期 / 展开后 0 天 → 不能生成，顶部 tip + alert。

### 3.2 明细表

| 列 | 说明 |
| --- | --- |
| 复选 | 新增，在序号前；表头全选（针对**当前可见行**） |
| 序号 | 按**全部已生成明细**的原始序号，过滤冲突项时不重排号 |
| 课程编号 / 课程名称 / 教师 / 日期 / 节次 / 原教室 | 现状 |
| 目标教室 | **选择器按钮**：有值回显教室名，无值「选择教室」；点击改该行 |
| 冲突情况 | 无冲突 / 有冲突 + 场地冲突说明 |

冲突行 `tr.is-conflict` 浅黄高亮（样式对齐时间侧）。

勾选「仅查询冲突项」：

- 只渲染 `conflict.hasConflict` 的行；无冲突时表体空态：「当前没有冲突明细」。  
- 不勾选：渲染全部已生成行。  
- 切换勾选不重新 `collectAdjustmentBatchHits`。

「调教室」：

- 未生成明细 / 当前可见行无一勾选 → 提示先勾选。  
- 打开选教室弹窗，确定后把教室写入所有勾选行的 `targetRoom`，重算冲突并刷新 tip。  
- 目标教室与该行原教室相同：允许（表示改回），冲突按占用重算。  
- 表单级「目标教室」不随多选改教室改写（避免和生成条件 key 纠缠）；提交以**行上** `targetRoom` 为准。

### 3.3 提交

1. 须已生成明细、已填调整原因。  
2. `countAdjustmentBatchRoomConflicts(全部 preview)` > 0 → 不允许提交（不受「仅查询冲突项」过滤影响）。  
3. 写回课表：`r.slot.room = r.targetRoom`（不要再用表单级统一教室覆盖行值）。

## 4. 数据与状态

```javascript
ADJUSTMENT_BATCH_STATE.room = {
  dates: [], range: { start: '', end: '' },
  dateMode: 'date',          // 'date' | 'weekday'
  weekFrom: 0, weekTo: 0, weekdays: [],
  preview: [], files: [],
  sourceRoom: '', targetRoom: '',
  generatedKey: '',
  conflictOnly: false,       // 「仅查询冲突项」
  selectedIdx: new Set()     // 勾选的 preview 下标（相对全量 preview）
}
```

明细行在现有字段上增加：

```javascript
{
  ...hit,
  targetRoom,                // 可被行内 / 批量调教室改写
  targetDateStr: dateStr,    // 与源日期相同，供冲突检测
  targetPeriod: period,
  targetWeekday: weekday,
  targetWeekNo: weekNo,
  conflict: { teacher: [], student: [], room: [], hasConflict }
}
```

`generatedKey` 仍只由「源日期 + 源节次 + 源教室 + 表单目标教室 + 日期模式/起止周/星期」组成。行内改教室、勾选、仅查冲突 **不** 改变 key，因此不必先清空再生成。

## 5. 模块改动

### 5.1 HTML（`#adjustment-batch-tab-room`）

源日期块对齐时间侧结构：

- `.adj-batch-date-mode`：`data-kind="room"` 的按日期 / 按星期按钮。  
- `#adjustment-batch-room-date-pane` 包住现有日期按钮。  
- `#adjustment-batch-room-weekday-pane`：`week-from` / `week-to` / `weekdays` + `weekdays-mount`，id 前缀 `adjustment-batch-room-`。

操作区：

- 清空后增加 `<button … onclick="openAdjustmentBatchRoomRowsPicker()">调教室</button>`。  
- 增加 `<label class="adj-batch-conflict-only"><input type="checkbox" id="adjustment-batch-room-conflict-only"> 仅查询冲突项</label>`，默认不勾。

表头：

```html
<th class="col-check"><input type="checkbox" … 全选可见行></th>
<th class="col-index">序号</th>
…现有列…
<th>目标教室</th>
<th class="adj-batch-conflict-col">冲突情况</th>
```

表增加 class：`adj-batch-room-preview`（高亮、冻结复选列）。左冻建议 `adj-freeze-left-3`（复选 + 序号 + 课程编号）或至少冻复选+序号，实现时与时间侧冻结策略对齐、避免挡占用列。

### 5.2 JS

**日期模式（复用并修 kind 泄漏）**

1. `ADJUSTMENT_BATCH_STATE.room` 补 `dateMode` 等字段。  
2. `onAdjustmentBatchDateModeChange` / `onAdjustmentBatchWeekdayFieldChange` / `initAdjustmentBatchWeekdaySelect`：  
   - `kind === 'room'` → `clearAdjustmentBatchRoomPreview` + `renderAdjustmentBatchPreview('room')`；  
   - `kind === 'time' | 'timeTarget'` → 维持现逻辑。  
3. `validateAdjustmentBatchRoomForm` 增加 `validateAdjustmentBatchWeekdaySide('room', '源日期')`。  
4. `getAdjustmentBatchRoomSelectionKey` 拼上 `dateMode/weekFrom/weekTo/weekdays`。  
5. `resetAdjustmentBatchForm('room')` 复位日期模式与 `conflictOnly` / `selectedIdx`。  
6. 打开教室 Tab / 学期变更时 `syncAdjustmentBatchDateModeUi('room')`。

**冲突**

新增（教室侧专用，勿改时间侧函数行为）：

- `checkAdjustmentBatchRoomRowConflict(row, allRows, idx, occ)`  
  - 目标星期/节次/周次 = 源（`dateStr` / `weekday` / `period` / `weekNo`）。  
  - **不要** `sameAsOriginal` 直接 return。  
  -  occupancy 命中目标教室且不是本行原 `slot` 时记场地冲突。  
  - 其它明细行若同日落点、同一 `targetRoom`，互记场地冲突。  
  - `hasConflict = result.room.length > 0`。  
- `annotateAdjustmentBatchRoomConflicts(rows)`  
- `countAdjustmentBatchRoomConflicts(rows)`  
- 单元格可复用 `renderAdjustmentBatchTimeConflictCell`（仅场地时 types 为「场地冲突」）。

生成后、行内改教室后、批量调教室后都要 `annotate` + 刷新 tip。

**明细渲染 `renderAdjustmentBatchPreview('room')`**

- `emptyColspan` 改为 10（+复选 +冲突）。  
- 可见行 = `conflictOnly` ? 冲突行 : 全部。  
- 每行：复选（`data-idx` 用全量下标）、序号用全量 `idx+1`、目标教室按钮 `openAdjustmentBatchRoomRowPicker(idx)`、冲突单元格、`is-conflict`。  
- 勾选状态读 `selectedIdx`；过滤后全选只作用于可见下标。

**行内 / 批量改教室**

| 动作 | mode（建议） | 确定后 |
| --- | --- | --- |
| 点某一行目标教室 | `batchRoomRow` + `adjustmentBatchRoomRowIndex` | 写该行 `targetRoom`，annotate，render |
| 点「调教室」 | `batchRoomRows` | 写所有 `selectedIdx` 的 `targetRoom`，annotate，render |

`confirmScheduleRoomSelection` 里对上述 mode **早返回**，不要走进 `batch` 源/目标教室或 `batchTimeRow`。  
确定时校验：所选教室不能空。是否禁止等于源教室：行内改教室允许改回原教室；批量改若与某行原教室相同则该行无场地变化、冲突按占用算。

**仅查询冲突项**

`onAdjustmentBatchRoomConflictOnlyChange`：写 `conflictOnly`，`renderAdjustmentBatchPreview('room')`。不清 `preview`。

**提交 `confirmAdjustmentBatch('room')`**

- 对 **全量** preview 计冲突，>0 则 alert + tip，return。  
- 写回使用 `r.targetRoom`。

### 5.3 CSS

- 日期模式、星期字段：教室 Tab 直接吃 `#modal-adjustment-batch .adj-batch-date-mode*` / `.adj-batch-weekday-*`（时间侧已有）。  
- 冲突高亮：把现有 `.adj-batch-time-preview tr.is-conflict` 规则扩到 `.adj-batch-room-preview`，或抽公共 `.adj-batch-preview-table tr.is-conflict`。  
- 「仅查询冲突项」、操作按钮组间距。  
- 目标教室按钮与时间侧 `.adj-pick-btn` 回显一致。  
- 复选列宽度、冻结列背景（含冲突高亮时冻结格也要浅黄）。

## 6. 实现任务（建议顺序）

1. `ADJUSTMENT_BATCH_STATE.room` 扩字段；修日期模式 / 星期多选的 kind 分支，避免清掉时间明细。  
2. HTML：源日期切换 + 按星期面板。  
3. `validateAdjustmentBatchRoomForm` / `generatedKey` 接入按星期。  
4. 冲突检测 + 列 + 高亮 + 顶部 tip；提交拦截冲突。  
5. 明细目标教室选择回显（独立 picker mode）。  
6. 复选列 + 「调教室」批量改教室。  
7. 「仅查询冲突项」过滤展示。  
8. 提交改为按行 `targetRoom` 写回。  
9. 自检：只测批量调教室时，批量调时间、排时间、排教室、审批选教室行为与改前一致。

## 7. 验收要点

1. 默认仍是按日期选源日期；切到按星期后出现起始周、截止周、星期多选，节次仍是下方源节次格。  
2. 按星期未选全不能生成；展开后的日期出现在摘要中。  
3. 切回按日期 / 改星期会清教室明细，**不清**时间 Tab 明细。  
4. 生成后冲突列有「无冲突 / 有冲突」；冲突行浅黄；顶部有条数提示。  
5. 把多门课调进同一已被占用的目标教室，对应行出现场地冲突；改教室后冲突刷新。  
6. 点明细目标教室可改该行并回显；点「调教室」须先勾选，确定后批量回显。  
7. 「仅查询冲突项」默认关；打开后只看到冲突行，关掉看到全部；序号保持生成时的序号。  
8. 有冲突时底部「确定」不能提交；无冲突时按各行目标教室写回，而不是表单上那个初始目标教室一刀切。  
9. 回归：批量调时间按星期 / 调后教室 / 冲突列仍可用；排教室、排时间详情、审批选教室无回归。
