## Context

分组工作台名单页（`#offering-group-student-panel`）已有「预置名单分配」「添加学生」「调整分组」。预置分配偏批次勾选入组，缺少：

1. 无平行小组时按专业+intake 一键整班导入；
2. 多平行小组时按国籍类型/专业/intake/性别配置模式与优先级的自动拆组。

学生属性原型已具备：性别 `gender`、国籍/学生类别可映射至 Local/Chinese/International（见 `SCHOOL_ELECTIVE_STUDENT_TYPES` 与 mock 规范化）、专业与入学批次。小组有 `capacityLimit`。任务「生效」后名单仍可维护（既有 `assertOfferingGroupingStudentEditable`）。

## Goals / Non-Goals

**Goals:**

- 工具栏「一键分配」；按是否存在平行名单小组自动分流场景
- 无特殊分组：匹配学生一次性入课程班
- 自定义规则：配置弹窗 → 执行引擎 → 写回小组归属；支持学号顺序与小数兜底
- 结果可预览/确认，剩余与超容可解释

**Non-Goals:**

- 替换或删除「预置名单分配」
- 通识开放选课由选课应用生成名单的主路径
- 正式库级排课/选课系统对接（原型用现有预置池）
- 改分组创建 UI（组数与容量仍由既有「分组」流程维护）

## Decisions

### 1. 场景判定

- **无特殊分组**：`!(sec.groups?.length)`，或仅有学时类型安排而无「名单平行小组」（以 `sec.groups` 为空为准；若仅 hour-type 拆分不建 groups，走本场景）。
- **自定义规则分组**：`sec.groups.length >= 2`（或 `>= 1` 且业务视为平行组）。**采纳**：`groups.length >= 2` 为自定义规则；`groups.length === 1` 仍可走规则或整班入该组——**原型：1 组时等同无特殊分组入该唯一组**；≥2 走规则配置。

### 2. 学生池与匹配范围

- 池：当前课可分配预置/合格学生（复用预置名单候选逻辑），排除已在本课名单且已锁定不可覆盖者；一键分配默认**覆盖未分配与可重分的预置生**，不覆盖「手动添加」学生（与预置分配跳过手动的习惯一致）。
- 无特殊分组匹配：学生 `programme`/`programmeKey` + `intake` 落在本课开课专业批次集合内则入池。

### 3. 规则配置模型

```text
{
  dimensions: [
    { key: 'nationalityType'|'programme'|'intake'|'gender', mode: 'proportional'|'sequential'|'unique', priority: 1..n }
  ],
  sortByStudentId: true|false   // Y/N
}
```

- 至少勾选 1 个维度；优先级可拖拽或数字，唯一且升序执行。
- 国籍类型取值：Local / Chinese / International（映射现有国籍/学生类别字段）。
- 性别：Male / Female。

### 4. 单维分配算法（N 组，组容量 `cap[i]`）

池内先按 `sortByStudentId` 排序（Y：学号升序；N：稳定伪随机打散，原型用 seeded shuffle）。

- **等比例**：对各维度类别，将类别人数尽量按 1/N 分到各组；目标人数 = round(类别人数 × cap[g]/总容量) 或按用户示例「每组取类别总人数的 1/N」——**采纳用户示例：每组目标 = round(类别人数 / N)，再按组容量裁剪，最后用兜底校准对齐 cap**。
- **按顺序**：按类别固定顺序（专业代码/intake 字序；国籍 Local→Chinese→International；性别 Female→Male 可配置，默认字母序）依次填满组 1…N。
- **唯一值**：尽量一组一类；同类按序填满一组再开下一组；剩余溢出进最后一组或「待分配」——**采纳用户示例：超出容量进后续组混合，仍受 cap 限制，放不下进 leftover**。

### 5. 多维嵌套

高优先级维度先产出每组的「名额构成」或学生子集；低优先级在**每个高维子集内部**再按自身模式细分。实现上优先「先算名额矩阵再抽学生」，避免双重随机。

### 6. 兜底校准

比例出现小数：先四舍五入；若各组合计 ≠ 目标，从人数最多/最少的组 ±1 微调，直至满足各组 `capacityLimit`（不超过）且尽量吃满计划入组人数。

### 7. UI

- 工具栏按钮「一键分配」。
- 无特殊分组：二次确认（展示匹配人数）→ 执行。
- 自定义规则：模态配置维度/模式/优先级/学号开关 → 预览各组人数构成（可选首版简化为确认文案）→ 执行 → toast/摘要（成功数、leftover）。

### 8. 与预置名单分配关系

并存。一键分配偏「规则引擎」；预置名单分配偏「勾选批次预览确认」。文案区分，避免用户混淆。

## Risks / Trade-offs

- [唯一值 + 多维嵌套结果难预期] → 预览摘要 + leftover 明确列出。
- [手动生被跳过导致组未满] → 结果提示已跳过手动人数。
- [等比例「1/N」与「按组容量加权」不一致] → 文档钉死采用用户示例的 1/N，再 cap 裁剪。
- [性能] → 原型人数百级足够；算法 O(学生×维)。

## Migration Plan

1. 加按钮与场景分支。
2. 实现无特殊分组导入。
3. 规则弹窗 + 单维三种模式 + 学号开关。
4. 多维优先级 + 兜底校准 + leftover。
5. 演示数据覆盖 ACC/FIN × 国籍示例。

回滚：隐藏按钮即可。

## Open Questions

- 按钮文案：无特殊分组场景是否显示为「无特殊分组导入」？**默认**：统一「一键分配」，场景内文案区分。
- 已分配学生是否允许一键覆盖重分？**默认**：不覆盖手动；预置/一键来源可重分（二次确认提示）。
