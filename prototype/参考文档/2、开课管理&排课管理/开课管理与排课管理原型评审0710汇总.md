## 2. 方向性指引（跨模块）

### 2.1 三类开课 + 特殊场景

- **专业开课**：来自已提交的执行计划，按「专业 + 批次 + 课程」生成任务。
- **通识选修**：维护校选课程池后，由学院制定开课计划；名单主要来自**选课应用**，不在开课模块维护。
- **特殊/其他开课**：计划外需求（重修、补修等），教务手工维护计划与名单。

### 2.2 合班 vs 分组（重要命名与职责）

评审中反复强调二者**不是同一概念**：

```
执行计划行（多专业/多批次）
        │
        ▼ 合班（Merge）— 教务主导，学院可调整
   一条开课任务 / 教学班
        │
        ▼ 分组（Group）— 学院在任务安排阶段完成
   Group 1 / Group 2 / …
```

- **合班**：同一课程号、不同专业批次合成**一条**开课数据；前提条件与旧系统一致（课程号、起止周、教学周数、总学时、L/T/P/O 等一致）。
- **分班**：旧系统术语，易与「分组」混淆 → **建议 UI 统一叫「合班 / 拆班（退回）」**，分组单独叫「分组」。
- **合班时机**：应在**任务安排之前**完成；教务可先手动/半自动合班，学院后续可改。
- **权限**：教务与学院**都应具备**合班能力；教务做初步合班，学院有异议可调整。

### 2.3 开放选课 vs 不开放选课

- 属性在**修改教学任务**等环节设置；**默认不开放选课**。
- **不开放选课**：名单来自预置/手工维护，不走选课应用。
- **开放选课**（通识等）：名单由选课结果生成，开课侧**只读**；通识选修计划页不应出现「开放选课」的学院维护入口。
- 培养方案中标记为选修、但按专业批次上的课，仍走**专业开课**，不是通识流程。

### 2.4 人数与预置名单（评审重点讨论，尚未完全定论）

| 场景 | 倾向规则 |
|------|----------|
| 老生 / 已有预置名单 | 「计划人数」优先读**实际预置名单**人数 |
| 新生 / 尚无名单 | 读专业批次**招生计划人数** |
| 合班多批次 | 不能简单「相加」或「取最大」；需按业务规则汇总（评审中认为叠加/取最大都不对） |
| 学籍异动 | 异动**下学期生效**时，当前学期预置名单是否实时扣减/增加——**需与学籍模块对齐**（长讨论，暂定不实时生效或下学期再变） |
| 提前开下学期课 | 名单时点与异动生效时点存在**时差**；需明确「冻结点」而非实时联动 |

**方向**：减少教务人工核对；系统按规则自动算，仅极特殊情况手工 override。

### 2.5 教学任务默认项（排考/考勤等）

- 若学时为 0 或某类课默认不需要排考/考勤，**默认应为「否」**，避免学院逐条勾选。
- 保留「特殊情况调整」能力，但非常态操作。

### 2.6 下游：开课清单 → 授课确认 → 排课

- **开课清单**：汇总本学期已提交任务，是授课确认与排课的数据源（原型已预留）。
- **授课确认**：按教师汇总任务，邮件通知确认；触发方（学院 vs AC）**待定**。
- **排课**：消费清单/确认后的任务；需识别**不排课**、**共同授课**等标记。

## 3. 开课管理 · 分模块调整要点

### 3.1 准备阶段

| 功能 | 评审意见 |
|------|----------|
| **开课时间设置** | 学校级 + **单位级**可配置；单位设置**优先于**学校默认；不设则继承学校 |
| **操作流程图** | 必须保留，交给学院前需能看懂主路径 |
| **校选课程管理** | 维护选修课池、停复课、**可选专业**、**可选学生类型**；需增加 **Intake/年级批次** 维度（如仅 Year2 可选） |
| | 通识(G)与专业选修(M)若共用池子，Intake 规则要可配置；是否在选课端校验 vs 开课端维护——**倾向开课端维护、选课端校验** |

### 3.2 专业开课

| 功能 | 评审意见 |
|------|----------|
| **生成开课任务** | 来源：已提交执行计划 + 当前开课学期；支持筛选后**批量生成**（不必逐条勾选） |
| **列表字段** | 关注：上课学院/专业/批次、人数、起止周、开课单位、提交状态等；「计划总人数」逻辑见 §2.4 |
| **合班** | 前置到计划/任务安排前；同课程号多批次合并；教务+学院双权限 |
| **提交状态** | 计划提交后进入学院「任务安排」；提交前完成合班 |
| **预置名单** | 可查看/维护；正常情况不动；与执行计划、异动联动规则待细化 |
| **教学周/起止周** | 按开课学期读取校历；**不含考试周**；复习周调课另议 |

### 3.3 任务安排（分组 + 教师 + 学时）

| 功能 | 评审意见 |
|------|----------|
| **分组** | 学院负责；可按行政班批量建组；**提交前校验**：分组容量上限、教师/学时必须满足才可提交 |
| | 未分组时应提示且**不可提交**（或强提示） |
| **Support 教师** | 跨学院授课：需「Support/共享任务」机制——主办学院把任务共享给协办学院，协办学院教师带 Support 标记进入同一分组排教师 |
| | 首学期可 AC 按经验标记「需 Support」；学院确认或退回；理想态后续按历史自动推荐 |
| **教师安排** | 默认添加教师；Support 角色需区分 |
| **学时/教分** | 与 QA 沟通：**不宜做强限制**（长/短学期、14 周 vs 15 周等场景会少排或多排）；**按总学时汇总**为主，允许人工调整 |
| | 分组内可查看各组教师/学时分配情况 |
| **提交校验** | 分组人数上限、必要字段齐全；允许「软提交+确认」的提法被讨论，但最终倾向**硬校验** |

### 3.4 学生名单

| 功能 | 评审意见 |
|------|----------|
| **专业开课名单** | 预置 + 手动 + 学籍异动；需**变更日志**追溯（原型后续已加「开课名单变更日志」） |
| **通识选修名单** | **不在此维护**，来自选课应用 |
| **特殊开课名单** | 教务手工添加 |
| **异动** | 下学期生效的异动不应影响当前学期名单；实时同步 vs 学期冻结——**倾向冻结/下学期处理** |

### 3.5 通识选修 & 特殊开课

| 类型 | 评审意见 |
|------|----------|
| **通识选修** | 计划从校选课池添加；任务安排流程与专业类似但**无合班**（或极少）；提交后进清单 |
| **特殊开课** | 教务手工加计划；维护预计容量；提交后分组、安排教师；名单手工维护 |

### 3.6 开课清单 & 共同授课

| 功能 | 评审意见 |
|------|----------|
| **开课清单** | 展示本学期全部已提交课程；供确认与排课消费 |
| **授课确认** | 按教师汇总任务发邮件；数据格式、触发角色（学院/AC）**待定** |
| **共同授课** | 不同课程号、内容相近、**同一教师**；用于排课时忽略该教师课程间冲突 |
| | **不是**「同一分组多门课」；是**不同课、同一教师、同一时段一起上**（合班上课语义） |
| | 需与排课模块约定：共同授课码、冲突豁免规则 |

## 4. 排课管理 · 评审要点

### 4.1 与开课衔接

- 排课抓取**已进开课清单/已确认**的任务。
- 需识别：是否排课、是否排场地、共同授课、Support 教师等来自开课侧的标志。
- **不排课**的课程不应进入排课操作（或单独过滤）。

### 4.2 排课时间与节次

- 人工排课习惯按 **8:00–22:00** 连续时段；系统改为维护**节次（Period）**及每节起止时间，课表展示仍用真实时间。
- **按学期**维护节次方案（后续时间调整可灵活变更）。
- 需维护：**午休**、**晚班/早班**时段标签，用于「晚课后避免次日早课」等规则。

### 4.3 排课模式

- **课程排** vs **教师排** 两种视角都需要。
- 按**总学时**排课（与开课侧一致）；L/T/P 细分在人工排课时可识别，系统层以总学时为主。
- 冲突检测：教师冲突、教室冲突等（评审后半段演示讨论）。

### 4.4 共同授课在排课侧

- 设置共同授课码后，同一教师多门课**时间冲突可豁免**（仅限共同授课场景）。
- 与「分组内多课」无关；分组是学生维度，共同授课是教师+多课程号维度。
