## Goals / Non-Goals

**Goals:**

- 三页去 hidden，查询区 / 工具栏 / 列表壳对齐专业开课。
- 开课安排改成样式二两步，安排教师 / 管理名单仍进现有分组沉浸页。
- 数据层坚持：无 programmeKey / intake；名单无预置池。

**Non-Goals:**

- 合并专业开课与特殊开课为同一列表。
- 从执行计划生成特殊开课。
- 按批次合班、Support、预置/招生计划人数、按批次一键分配。
- 改专业开课或选修开课行为。
- 本期不产出特殊开课 PRD 升版（未要求）。

## Decisions

### D1 · 保留三页 ID，不新建路由

继续用 `#page-course-offering-other`、`#page-course-special-offering-task`、`#page-course-special-offering-roster` 与现有 `data-page`。去掉 `hidden`，改壳与渲染。

备选：三页合成一页（像选修安排）——否决，专业开课是分三页，用户选的是对齐专业开课。

### D2 · 开课安排复用样式二交互，数据过滤 `other`

安排页加上 `mot-style2-step-bar`（Course Setting / 师资安排），列表与步骤操作对齐专业开课样式二，数据只含 `offeringType=other`。不与专业开课共用同一 DOM 列表，避免筛选项（上课专业等）串台。

分组继续 `openOfferingGroupingModal(..., { returnPage })`；`OFFERING_GROUPING_RETURN_LABELS` 改为「开课安排 / 开课名单」。

备选：参数化专业开课样式二一套 DOM——改动面大、筛选项差异多，本期不拆公共组件。

### D3 · 加课入口保留课程库勾选弹窗

计划页「添加开课计划」仍打开现有「添加特殊开课计划」课程库选择器。添加结果：一条课一个教学班，不写专业批次。容量沿用现有预计容量 / 预留名额（无预置口径）。

### D4 · 列表与筛选去掉批次维度

计划 / 安排 / 名单均不展示、不筛选「上课专业」「上课批次」。任务页现有专业 / 入学批次列去掉。所属部门、课程号等与专业开课同类筛选项可保留（不依赖批次）。

「所属专业」若出现，仅表示课程库开课单位/所属专业档案，MUST NOT 当作上课专业批次。

### D5 · 名单无预置池

管理名单进入分组页学生 Tab 后，只有手工添加 / 移除。不提供按专业批次预置、一键按类别分配（那些依赖批次名单）。人数上限仍以课程名额 / 小组上限为准（现有分组页能力），来源是手工填的容量，不是预置人数。

### D6 · 演示数据

启动时不再走 `migratePurgeSpecialOfferingPlanData` 清掉 other（菜单已恢复）。不为特殊开课注入执行计划式生成结果。空学期允许空表；演示靠用户手动添加。不恢复 `ensureSpecialOfferingTaskPageDemos` 的旧样例注入，除非实现时需要一条可点通的样例——若加，必须是手动添加形态，且无批次字段。

## Risks / Trade-offs

- [样式二逻辑与专业开课高度耦合] → 复制交互壳 + 独立 page id / 过滤 other，不改专业开课函数默认行为。
- [历史 other 行可能带旧批次字段] → 列表忽略批次展示；新添加不写批次。
- [三页曾 hidden，goPage 仍已挂接] → 去 hidden 后即可进页；核对渲染入口是否完整。

## Migration Plan

- 原型：去 hidden、改侧栏文案、改三页壳与渲染；加课弹窗保留。
- 回滚：恢复 hidden 与旧列表即可，数据模型仍是 `offeringType=other`。
