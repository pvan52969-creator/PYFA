## Goals / Non-Goals

**Goals:**

- 把未确认项与原型自相矛盾处钉在 OpenSpec，实现时有边界
- 本 change 落地时只做「盘点可见」：不扩正式 PRD、不改生命周期规则

**Non-Goals:**

- 不写选修计划 / 名单正式 PRD
- 不把专业开课撤回/退回/权限套到选修
- 不关闭选课端 UC003
- 不归档未完成的 `ge-quota-by-g-type` 等旧 change（只作过程债记录）

## Decisions

### 1. 隔离专业开课拍板，不默认同步

- 选择：选修单独确认。
- 备选：默认与专业开课同一套——否决，用户此前明确选修安排正式 PRD 要等客户原型确认。
- 理由：专业开课「退回=仅未生效、清空分组教师」与选修原型「名单页退回已生效、安排函数保留分组」已经打架。

### 2. 模块名与后续文档分写

- 用户可见入口：整页称「选修开课 / 选修开课安排 / 选修开课计划」（含 GE 与 ME）；GE 专属操作称「GE 开课」，不把整页叫「通识选修开课」。
- 界面已用 GE / ME 两个 Tab 分开操作。**以后写需求文档时 GE、ME 必须分开写**（两节或两份），不要混成一段。现在仍不生成正式 PRD。
- 本 change 不改撤回/退回业务分支，不写计划/名单正式 PRD。

### 3. 配额「不拦截生效」不升格为已明确

代码注释不能当 PRD。保持未确认，除非用户当面确认。

## Open Questions

已拍板（2026-09-09 用户回复，不写入选修正式 PRD）：

- 选修「计划」是教务定的人数/组数**标准**，不是专业开课那种「先计划再生效再安排」。学院/专业按标准自己决定开哪些选修课。
- **撤回可以有**。专业开课与选修开课同一前提：还没排课才能撤；已经排课须先由**排课板块清除已排数据**后再撤。
- **选修「退回」**：从**生效 → 草稿**；**授课确认不变**，已确认的仍是已确认。（不是专业开课那种「未生效退回计划、清空分组教师」。）
- **专业开课：名单「退回」= 安排页「撤回」，同一效果、不同入口/角色：**
  - 效果：已生效的开课安排 → **草稿**；**授课确认状态不动**（已确认仍是已确认）。
  - 开课安排「撤回」：学院发起。
  - 开课名单「退回」：教务发起。
  - 开课安排「退回」仍是另一件事：安排草稿 → 开课计划。
- **授课确认何时变为未确认**：仅当已确认的开课安排被回头编辑，且已确认的安排内容实际变化并保存时。撤回 / 名单退回 **不** 取消授课确认。原型：分组工作台与课程信息抽屉在已确认且可编辑时提示；保存后若指纹变化则教师确认包失效。
- 对照：现行开课名单 PRD BR002 仍写成「与安排退回同一套」——与本次不符，尚未升版。
- 用户可见旧名「通识选修开课」已改为「选修开课安排」等（整页含 GE+ME）。

仍未确认（会改变后续实现，不能猜）：

1. 选修的「撤回」和「退回」是不是同一操作（都是生效→草稿）？若是，安排页/名单页按钮用哪个名字？
2. 已排课：是用户自己去排课计划清掉，还是开课点撤回/退回时系统通知/调用排课清？（原型专业开课已是「请先撤销排课结果后再撤回」）
3. 选修数据权限按专业、按学院、还是按开课单位？
4. GE 类型配额未达标能否生效？
5. 名单是否一律等选课应用生成？ME 是否同一口径？
