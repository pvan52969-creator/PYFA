## Goals / Non-Goals

**Goals:**

- 12 份菜单 PRD 均按 V3 章节写齐：文档信息、菜单范围、界面结构树与关系表、界面详情、字段状态矩阵、功能与交互、业务规则、数据流转、流程、原型对应、未确认事项
- 每个改动对象可追溯到 P / FD / F / BR / UC ID；变更说明总览引用这些 ID
- 补齐 `prd_folder_paths` 中「授课教师替换」「排课计划」的一级/二级映射（课程班管理下续号）

**Non-Goals:**

- 不改原型交互、不重做选修开课三菜单、不批量回改历史 V2 变更说明
- 不把变更说明写成迷你 PRD（不抄完整字段矩阵）
- 本次不强制同步生成概要/详细设计（与 `course-modules-hld-lld-docs` 分开）

## Decisions

1. **交付形态：按菜单手工/脚本填充 V3，而非整仓自动 diff**  
   - Rationale：V3 核心是界面树与状态矩阵，需对照原型人工建 ID；纯脚本从旧 V2 无法可靠推断 Add/Edit/View。  
   - Alternative：仅改模板外壳、正文粘贴旧表 → 否决（对不上 V3 评审口径）。

2. **版本号：在上一有效版上 +1，日期用实施当日**  
   - Rationale：与现规范一致；跳号仅在中间版作废时发生。  
   - Alternative：全部重置为 V1（V3 结构）→ 否决（破坏菜单内版本链）。

3. **目录：授课教师替换 = `05_课程班管理/05_授课教师替换`；排课计划 = `05_课程班管理/06_排课计划`**  
   - Rationale：侧栏顺序在课程班管理末两位；01–04 已占用。  
   - Alternative：新建一级菜单 → 否决（与侧栏不符）。

4. **实施批次：先映射与脚手架 → 开课设置 3 → 专业开课 3 → 课程班管理 6**  
   - Rationale：设置/专业开课已有较完整 V2 可迁移；课程班管理含两份首版，风险集中后置。  
   - Alternative：12 份并行一次交 → 易漏未确认项，难评审。

5. **未知规则一律 UC +「未确认」，禁止编造接口字段/学校政策**  
   - Rationale：产品 Agent 规则；原型未体现处不得脑补。

## Risks / Trade-offs

- [工作量大 / 字段矩阵易漏] → 按菜单 checklist（界面树先于字段）；每菜单先出 md 评审再出 docx  
- [旧 V2「功能清单」与 V3 F001 编号不对齐] → 变更说明用「澄清/修改」写明映射关系；不强制旧序号等于新 F ID  
- [原型页内 Tab/抽屉未挂侧栏] → 仍编入该菜单界面树（如分组工作台挂开课安排），不另开菜单 PRD  
- [排课计划与外部排课 DEMO 边界] → PRD 只描述本仓库 `page-course-scheduling-plan`；下游排课系统交互标未确认  

## Migration Plan

1. 更新 `scripts/prd_folder_paths.py` 与规范目录说明  
2. 按批次写入新版本文件夹（md 先行，docx 对齐模板）  
3. 同步变更说明 V3  
4. 抽检：每菜单至少 1 个 FD 含 Add/Edit/View；变更说明对象 ID 能在 PRD 中找到  
5. 回滚：删除未确认的新版本文件夹即可（不碰旧版）
