## 1. 文档概述

### 1.1 文档目的

明确开课安排列表（2 步）、行展开安排预览、分组工作台（侧栏/树/安排详情）、共同授课与联动、授课确认入口、Teaching Load / 课时详情等界面、字段、交互与 tip 业务规则，供产品、研发、测试与 AI 后端统一依据。

### 1.2 填写口径

- 「（已明确）」：原型可见文案或 tip/alert 已写明。
- 「（未确认）」：未讨论或占位。评教字段见 BR015（已明确占位，不接真接口）。
- 界面 ID 写成 `编号（中文名）`。
- 教室偏好类型为**多选下拉**，禁止写成自由文本。

### 1.3 建设背景

计划生效后完成 Course Setting 与师资安排（分组、学时行、教师、场地偏好、共同授课/联动、授课确认），支持安排生效；停课主入口在课程班。

- Teaching Load：按学期等维度展示教师学时（标题含 tip）。
- 课时详情：点教师相关入口；含 No. of Groups(!)、Latest Evaluation(!) 等列。

### BR001 分点清单（生效校验；对照确认生效弹窗）

**A. 硬阻断**（确认生效按钮禁用，不可生效）

1. 任务已停课 →「已停课，无法生效。」
2. 选修（enrollmentType=open）计划总人数未填（空；`0` 算已填）→ 须先在「修改教学任务」填写，未填写无法生效。
3. 有小组时的结构：组名不能为空、组名不能重复；每组人数上限须有效（>0）；各组上限合计不能超过课程人数上限；合计不能低于计划人数（无法覆盖计划人数）。（名单模式下「名单人数超过上限合计」属保存/分配路径提示，生效本条只按计划人数与课程人数上限。）
4. 师资/学时不完整（**不含**文案「尚未录满」）：
   - 无小组按课程班维度判定；有小组按每个小组判定。
   - 计划学时 > 0 的学时类型（合并模式看合并后总量）：该对象必须已安排教师；已有安排行则须指定授课教师、起止周、周学时（已填且 ≥0）。
   - 有安排行但未选择课程组 →「未选择课程组」（可暂存，不可生效）。
   - 四学时全为 0：仍须至少安排教师（「尚未安排教师」），否则硬阻断。
   - 计划为 0 的学时类型：不强制安排，允许超学时安排。
   - 已安排真实教师时 Course Coordinator 必填（一名教师强制默认；未设则「请设置 Course Coordinator。」）。见 BR019。
5. 授课确认：该任务下真实教师（排除 TBC）须全部为「已确认」或「管理端代确认」。未下发 / 待确认 / 已不同意 → 硬阻断；提示含姓名与状态。无真实教师则本项通过（仍可能因第 4 点「尚未安排教师」被拦）。
   - **例外（非本入口）**：已生效后经「授课教师替换」（见该菜单 BR001）或已确认安排被改动保存（BR018）导致确认回退时，安排可保持已生效。本「确认生效」入口不适用该例外，再生效仍须齐套确认。

**B. 二次确认仍可生效**（按钮可用，弹窗警示）

6. 欠学时：已录入学时 < 计划且文案为「尚未录满」→ 提示「学时尚未排满，确认后仍可提交」。
7. 超学时：已录入 > 计划 → 提示「已超过计划学时，确认后仍可提交」。不阻断。

**C. 生效成功副作用**（确认框说明文案）

8. 生效后锁定合分班、分组与教师安排。
9. 须全部授课教师已在系统内完成确认（含代确认）——与第 5 点同一条件。
10. 必修可在「开课名单」按小组维护名单；选修默认名单由选课应用生成，仍可在「开课名单」维护。

**D. 保存 vs 生效**

11. 第 3 点结构错误：保存与生效均阻断。
12. 第 4 点不完整与第 6–7 点学时偏差：保存允许（提示后续完善 / 仍可保存）；生效按 A/B。
13. Course Coordinator：有真实教师时保存与生效均必填（BR019）。

## 12. 状态枚举与转移（后端必读）

### 安排生效状态

- 字段：taskSubmitStatus（列表「生效状态」）
- 枚举：`draft` / `submitted` / `reverted` / `cancelled`
- 转移：draft→submitted（须满足 BR001 **A 硬阻断**项全部通过；欠学时/超学时仅二次确认，不阻断）；submitted→draft 经「撤回」（BR003，授课确认不变）或开课名单「退回」（与撤回同一效果）；未生效经「退回」使计划 submitStatus→reverted（BR003）；→cancelled 经课程班「设置停课」；禁止与授课确认进度合并成单字段。

### 授课确认进度

- 列表「授课确认」为教师确认包进度（已确认 / 部分确认 / 未确认），不是安排生效状态。
- 已确认 → 未确认：仅 BR018（已确认安排内容变化并保存）或《授课教师替换》BR001。撤回、名单退回不转移确认态。
- 再生效仍须 BR001 第 5 点齐套。

### 同时授课

- 取值：空 | 是 | 否；新增默认空（BR010）。

## 14. 后端实现约束

- 规格真源：可见 UI + tip/alert + 本文「已明确」；禁止猜测未确认项。
- 教室偏好禁止自由文本；须多选教室号，空=无偏好。
- 同时授课禁止擅自默认「是/否」。
- Latest Evaluation 按占位实现，禁止伪造评教库。
- 不做 OpenAPI 全文。
- 数据权限：开课模块数据权限按专业：操作人有该专业权限即可查看并操作该专业所属数据；未授权专业不可见。本口径仅约束开课模块。
- PRD 旧三步作废；必须 2 步。
