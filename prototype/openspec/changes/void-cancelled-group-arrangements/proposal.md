# Proposal

## Why

课程组停课后，学时安排表仍保留该组行并可编辑/复制，新增时也能勾选已停组；名单侧仍可把学生放进已停组。这与「组停 = 该组安排作废、不可再作为业务目标」的口径冲突，教务无法从界面判断安排是否已失效。

## What Changes

- 课程组执行停课时：**作废（删除）** 仅属于该组的学时安排行；多组同行从目标组中移除已停组，若无剩余有效组则删除该行；已停组不再出现在安排详情列表中（无 ✎/⧉）。
- 新增/编辑学时安排时：**不可再选择已停课组**（下拉禁用或直接不展示可选）。
- 关联业务自查并禁用已停组：至少覆盖分组学时安排、排课计划入列、Teaching Load 计入、共同授课/联动若依赖该组安排等下游（以原型现有入口为准）。
- 名单管理：**不可将学生分配进已停课组**；若停课前组内已有学生，停课后这些学生变为**未分配小组**。
- 停课确认 tip / 分组侧栏「停课」标识与上述作废结果保持一致（侧栏组节点可保留作只读历史，但安排与名单不再引用）。

## Capabilities

### New Capabilities

- `offering-group-cancel-cascade`: 课程组停课后的安排作废、选择禁用、名单解绑及关联业务禁用规则

### Modified Capabilities

- （无：主库 `openspec/specs/` 当前无已同步能力；本组行为以新 delta 能力承载）

## Impact

- 原型：`app.js` 中 `cancelOfferingGroupArrangement` 及学时安排表/草稿组选择、名单分配、排课计划过滤、Teaching Load 相关逻辑；必要时同步停课确认 tip。
- 产品文档：课程班 BR001 / 开课安排停课副作用说明宜后续升版对齐（本 change 以原型行为为准，PRD 升版可作为可选后续任务）。
- 不改变：整课停课（全部组停完 → 课级 `cancelled`）既有路径；停课仍不可撤销。
