## Goals / Non-Goals

**Goals**

- P0→P1→P2 依次把各菜单补到「可喂后端」：UI 树、字段矩阵、功能、tip→BR、实体/状态不自相矛盾。
- md/docx 章节一致；新增/修改处黄底。
- 教室偏好凡多选控件处禁止写成「文本」。

**Non-Goals**

- 不改原型代码。  
- 不重写开课安排。  
- 不发明 RBAC / OpenAPI / 校政。

## Decisions

1. **覆盖 V2（默认）** — 与开课安排用户确认策略一致。  
2. **分批交付** — 先 P0 六个，再 P1，再 P2；每菜单独立可验收。  
3. **名单工作台** — 与开课安排共用 `page-offering-grouping`：名单 PRD 写「学生名单模式」字段/按钮；安排侧已写的安排详情不重复整章，交叉引用。  
4. **确认两端** — 管理端与教师端分菜单写；共用列族可复制但 ID 各自编号。  
5. **生成方式** — 优先手工/专用脚本按 inventory 写满；批跑字典只扩 skip，不用缩水模板覆盖。

## Risks / Trade-offs

- [漏 tip] → 每菜单先写 INVENTORY 勾选再写正文。  
- [与开课安排重复] → 共用壳交叉引用，避免两份全文拷贝漂移。  
- [docx 缩水] → 每菜单用与开课安排相同的「从 md 全量生成 + 黄底」方式。
