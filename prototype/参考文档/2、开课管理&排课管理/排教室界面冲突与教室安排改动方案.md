# 排教室界面 · 冲突判定与教室安排改动方案

> 文档性质：代码改动方案（需求整理 · 实现指引）  
> 适用范围：排课管理 · 排课表教室（列表页 + 排教室详情）  
> 状态：关键规则已确认 / 已按方案直接改代码（跳过 OpenSpec） 
> 关联现状：`prototype/app.js`、`prototype/index.html`（`scheduleDetailPhase === 'room'`、选教室抽屉、三列表页）

---

## 1. 背景与目标

排课表教室侧承接「排课表时间」已提交数据，职责应收敛为：**仅为已排好时间的节次，按时间侧设定的场地类型安排具体教室**。

当前原型问题：

1. 排教室详情课表格仍可能按教师/学生/软冲突着色，与「只关心教室」的定位不符。  
2. 选教室确认时几乎无校验（仅落库有「同教室时段重叠」检测能力，座位与类型未校验）。  
3. 详情左侧课程列表仍按学时完成度展示，未统一为「排教室状态」。  
4. 选择排课教室时，看不到当前节次在时间侧配置的场地类型、场地备注。

### 1.1 本期目标

| # | 目标 |
|---|------|
| G1 | 排教室界面**只判定并展示教室类冲突**（三类，见 §3） |
| G2 | 排教室界面**只安排教室**：不改时间；依据时间侧节次上的 `venueTypes` / `venueRemark` |
| G3 | 课程列表（含详情侧栏）状态统一为**排教室状态** |
| G4 | 打开「选择教室」时，展示该节次的**场地类型 + 场地备注**提示 |

### 1.2 非目标

- 不改时间侧冲突模型（教师/学生/软冲突仍只在排时间侧使用）。  
- 不在教室侧开放新排时间、改周次、改场地类型（类型只读自时间侧）。  
- 不重做教室库主数据；复用现有 `SCHEDULE_ROOM_META` / 教室选择器数据源。  
- 发布课表、退回排时间流程逻辑本期不重构（可沿用现有按钮）。

  A -->|写入节次 venueTypes / venueRemark| B
  B -->|仅写 slot.room| C[课表发布/查询]

| 维度 | 排课表时间 | 排课表教室 |
|------|------------|-----------|

| 列表状态 | 排课状态（学时单元完成度） | **排教室状态**（节次是否已派教室） |
| 数据入口 | 全部可排任务 | 时间侧已提交范围 |

## 3. 教室冲突模型（仅教室侧）

排教室侧统一冲突口径，建议新增专用检测函数（勿直接复用时间侧全量 `detectSchedulePlaceConflicts` 着色）。

### 3.1 冲突类型一览

| 类型 key | 中文名 | 强度 | 判定规则 | 触发时机 |
|----------|--------|------|----------|----------|
| `roomTime` | 教室时间冲突 | **硬冲突** | 拟派/已派教室 `R`，与其他已排节次在同星期、重叠节次、重叠周次且 `slot.room === R` | 课表格着色、选教室确认、点击冲突格弹窗 |
| `roomSeats` | 座位数冲突 | **软冲突** | 节次关联**小组人数** `headcount` > 教室可用座位 `availableSeats`（无则回退 `seats`/`capacity`） | 同上 |
| `roomType` | 场地类型不一致 | **软冲突（二次确认可忽略）** | 节次 `slot.venueTypes`（排除「不选择教室」）与教室库 `roomType` / `classroomType` 映射后**无交集** | 同上 |

保存策略（已确认）：

| 冲突 | 选教室确认行为 |
|------|----------------|
| 仅有 `roomTime`（或与其它并存含时间） | **禁止保存**，提示时间冲突明细 |
| 仅有 `roomSeats` | 提示座位数冲突，**可继续排**（无需再弹二次确认也可强制保存；网格保留软冲突色） |
| 仅有 `roomType` | 弹出二次确认；用户可选择**忽略冲突继续排**并保存，或取消 |
| `roomSeats` + `roomType`（无时间） | 先汇总提示；类型项进入二次确认（可选忽略继续排），座位项软提示，忽略确认后一并保存 |
| 含 `roomTime` | 一律硬拦，不进入强制保存 |

多种教室冲突并存时：

- 课表格着色：`primary = 'mixed'` 或单独 `room` 色阶下用副类型区分（实现二选一，见 §7）。  
- 弹窗：分行展示三类明细，标题用「教室冲突」或「综合教室冲突」。

### 3.2 人数口径（已确认：小组人数）

实现时写死一处，避免列表与选教室不一致：

1. **优先**：节次关联上课小组的人数（`group.studentCount`；无则用 `capacityLimit`）。  
2. 多小组同节次：取各小组人数**之和**（同教室容纳全部小组）。  
3. 节次无小组绑定：回退教学班 `task.studentCount` / `sec.estimatedStudents`，并在选教室提示条标注「未绑定小组，按教学班人数」。

### 3.3 场地类型映射

时间侧类型（`SCHEDULE_VENUE_TYPES`）与教室库类型需建一张映射表，例如：

| 排课场地类型 value | 标签 | 可匹配教室库类型（示例） |
|--------------------|------|--------------------------|
| `lecture_room` | 普通教室 | Lecture Room / 普通教室 |
| `lecture_hall` | 阶梯教室 | Lecture Hall / 阶梯教室 |
| `computer` | 计算机教室 | Computer Lab / 计算机教室 |
| `specialty` | 专业教室 | Lab / Tutorial Room / 实验室 / 研讨型教室 等 |
| `auditorium` | 演讲厅 | Lecture Hall（或单独枚举，待确认） |
| `__none__` | 不选择教室 | **不校验类型**；可选教室时提示「时间侧未指定类型」 |

规则：

- `venueTypes` 为空：视为未指定 → 不报类型冲突，但 UI 提示「未设置场地类型」。  
- 多选类型：教室匹配**任一**即可（OR）。  
- 「不选择教室」与其它类型并存时：以其它类型为准校验；若仅 `__none__`，不强制类型。

### 3.4 教室时间冲突

沿用现有重叠逻辑（星期 + 节次区间 + 周次重叠 + 同教室号），但从时间侧「师生场地」大杂烩中拆出，专供教室侧调用。

## 4. 界面与交互改动

### 4.1 排教室详情 · 课表格

| 项 | 改动 |
|----|------|
| 冲突着色 | **仅**教室三类；关闭教师/学生/不排课/选修/教师时段/规则等在教室侧的网格着色 |
| 图例 | 教室侧图例收敛为：教室时间冲突 / 座位数冲突 / 场地类型不一致（可加「综合」） |
| 点击已排节次 | 选中节次；可弹窗查看该节次已派教室相关冲突（只读明细） |
| 点击空格 | 不可新排时间；若未来需要「空格预览」本期不做 |
| 场地类型控件 | 保持只读隐藏编辑；类型来自时间侧已保存的 `slot.venueTypes` |

### 4.2 选择排课教室抽屉（重点）

打开抽屉时（`openScheduleClassroomPickerModal` / 现有选教室入口），顶部增加**当前节次提示条**（必做）：

```
场地类型：普通教室、专业教室
场地备注：需靠近实验楼
人数：42　｜　星期：周一　｜　节次：3-4　｜　周次：1-16周
```

交互（已确认）：

1. 默认按场地类型预筛选教室列表（可取消筛选看全部）。  
2. 列表行可标注：座位数不足（软）/ 类型不符（软）/ 该时段已被占用（硬，可禁用该行或确认时硬拦）。  
3. 确认时跑 §3 三类检测，按 §3.1 保存策略处理。  
4. 提示条「人数」展示**小组人数**口径（见 §3.2）。

### 4.3 多节次多选 · 批量派同一教室（已确认）

支持在课表格多选多个已排节次后，一次选择教室并写入所有选中节次：

1. 选教室抽屉提示条汇总：选中节次数、各节次场地类型并集、备注（多条则分行或「多条备注」）、人数取**各节次小组人数的最大值**做座位软校验展示（保存时仍对每节次分别校验）。  
2. 确认时对**每一个选中节次**分别跑三类冲突：  
   - 任一节次存在 `roomTime` → **整批禁止保存**，列出冲突节次。  
   - 仅座位/类型软冲突 → 汇总提示；含类型不一致则**一次二次确认**，用户可选**忽略冲突继续排**后整批写入。  
3. 写入同一 `room` 到所有选中节次；节次间彼此重叠且同教室时，按时间硬冲突处理（选中集内部也要两两校验）。

### 4.4 课程列表 · 排教室状态

| 表面 | 现状 | 目标 |
|------|------|------|
| 三列表页（批次/教师/课程） | 已有「排教室状态」列（按 `slot.room`） | **保持**，文案与统计口径与详情对齐 |
| 详情左侧课程列表 | 按学时 `unit.complete`（未排完/已排完） | 教室侧切换为**排教室状态**：未排教室 / 已排教室（可按「该课全部已排节次是否都有 room」） |
| Tab「未排完/已排完」 | 学时维度 | 教室侧改为「未排教室 / 已排教室」计数 |

统计口径（与列表页一致）：

```
roomDone    = 已排时间且 slot.room 非空的节次数
roomPending = 已排时间且 slot.room 为空的节次数
已排教室    = roomPending === 0 && roomDone > 0
未排教室    = roomPending > 0 || roomDone === 0
```

「是否排课 = 否」的课程：不参与排教室统计（详情可不展示或单独灰显）。

## 7. 实现步骤建议

> 顺序：**先 OpenSpec → 再按下列分步改代码**。

### 第零步：OpenSpec（阻塞实现）

按 `openspec-propose` 产出 change，能力域建议：`schedule-room-assign`（或挂在现有排课教室 capability 下）。规格需写明：硬/软冲突、小组人数、多选批量派同一教室。

### 第一步：口径收敛（无 UI 大改）

1. 落地类型映射表 + **小组人数**函数。  
2. 实现 `detectScheduleRoomOnlyConflicts`。  
3. 教室侧网格着色与图例改为仅教室三类。  

**验收**：选中课程后，教室详情不再出现教师/学生冲突色；同教室重叠仍着色；座位冲突有软冲突色。

### 第二步：选教室提示与校验

1. 抽屉顶部展示场地类型、备注、小组人数、节次摘要。  
2. 确认时：时间硬拦；座位软提示可继续；类型不一致走二次确认，可选择忽略冲突继续排。  
3. 支持多选节次批量派同一教室（§4.3）。  
4. 列表行可选标注不可用原因。  

**验收**：打开选教室可见类型与备注；时间冲突无法保存；座位冲突可保存并保留提示；类型冲突二次确认时可忽略并继续排。

### 第三步：课程列表排教室状态

1. 详情侧栏 Tab/徽章改排教室口径。  
2. 与三列表页 `renderScheduleRoomArrangeStatusBadge` 文案对齐。  

**验收**：教室侧详情「未排教室/已排教室」与列表「排教室状态」一致。

### 第四步：示例与回归

1. 补演示数据覆盖三类冲突 + 多选批量派教室。  
2. 回归：时间侧冲突不受影响；提交→教室侧可见；退回排时间仍可用。

## 9. 验收标准

1. 排教室详情课表格**仅**显示教室时间 / 座位 / 类型（及综合）冲突色，无教师/学生/占位着色。  
2. 不能在教室侧新增或修改上课时间；只能为已排节次设置/清空教室。  
3. 选教室抽屉顶部展示当前节次的**场地类型**与**场地备注**（无则显示「未设置」）。  
4. 派教室时：**教室时间冲突硬拦不可保存**；**座位数冲突软提示可继续**；人数按**小组人数**。  
5. 场地类型不一致：二次确认时可选**忽略冲突继续排**并保存。  
6. 多选多个已排节次可**批量派同一教室**；含时间冲突则整批失败。  
7. 三列表 + 详情侧栏「排教室状态」口径一致（按节次是否已填 `room`）。  
8. 排时间侧原有冲突与提交流转回归通过。  
9. **实现前**已产出并通过 OpenSpec change。

## 10. 已确认结论与残留项

### 10.1 已确认（2026-07-22）

| # | 问题 | 结论 |
|---|------|------|
| 1 | 座位 / 时间冲突强度 | **座位 = 软冲突**（提示可继续）；**时间 = 硬冲突**（禁止保存） |
| 2 | 场地类型不一致 | 二次确认时可选**忽略冲突继续排**（取消则不保存） |
| 3 | 人数口径 | **小组人数**（多小组同节次取之和；无小组回退教学班） |
| 5 | 多节次多选 | **支持**批量派同一教室；逐节次校验，时间冲突整批硬拦 |
| 6 | OpenSpec | **实现前**先出 OpenSpec，通过后再改代码 |
