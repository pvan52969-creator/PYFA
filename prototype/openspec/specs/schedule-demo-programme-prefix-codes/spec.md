# schedule-demo-programme-prefix-codes

## Purpose

统一排课模块演示课号为「专业代码前缀 + 演示号段」，观感符合学校规格且不与真实开课目录撞号。

## Requirements

### Requirement: 演示课号前缀对齐所属专业

排课模块中面向用户展示的演示课程课号，SHALL 以所属专业的专业代码（三位英文字母，与 `PROGRAMMES` / 学校专业对照一致）为前缀。例如会计学专业批次演示课使用 `ACC…`，海洋环境化学（mec）使用 `MEC…`。MUST NOT 再使用与专业无关的演示前缀（如 `CDF`、`CDX`、`CTS`、`RM`、`RCL`）作为排课用户可见课号。

#### Scenario: mec 批次侧栏课号为 MEC 前缀

- **WHEN** 用户打开 mec|202409（或当前 lean 主演示批次）排时间详情并查看左侧课程列表
- **THEN** 原学生冲突锚点等演示课号以 `MEC` 开头，不再显示 `CDF201` 一类假前缀

#### Scenario: 跨批教师冲突同伴前缀随各自专业

- **WHEN** 教师冲突闭环依赖跨批已排同伴课
- **THEN** 各同伴课号前缀分别对应该课 `programmeKey` 的专业代码，而非统一假前缀 `CDX`

### Requirement: 演示号段避免与真课撞号

排课演示课号的数字部分 SHALL 使用约定演示号段（默认 **9xx**，如 `MEC901`），MUST NOT 直接占用用户提供的真实课程班导出表中已出现的课号（如真实 `MEC201`、`ACC312`）。通识 / MPU / 非三字母专业前缀课不在本条强制范围内，但排课演示专业课 MUST 遵守本条。

#### Scenario: 新课号不在真实导出表中

- **WHEN** 对照《课程班》真实导出中的课号集合
- **THEN** 本变更采用的排课演示课号均不落在该集合内

### Requirement: 课名与课组不强制对齐真实表

课程名称与课程组（短名）MAY 保持现有文案或任意合理英文/短名；本能力 MUST NOT 要求从真实导出表逐条同步课名与课组。展示格式仍遵循既有 Course Code / 课程班名称 / 课程组结构。

#### Scenario: 仅改课号仍可通过侧栏识别

- **WHEN** 演示课号已改为专业前缀 + 9xx，课名未改或仅微调
- **THEN** 侧栏仍显示课号与课名，交互与选课排课行为不变

### Requirement: 硬编码与闭环剧本同步更新

凡用户可见或脚本依赖的旧假前缀课号引用（种子数据、冲突剧本注释、变更日志演示摘要、查询样例说明等）SHALL 同步改为新课号，保证闭环冲突路径（学生 / 教师 / 场地）仍可按课号追溯到已排事实。

#### Scenario: 冲突弹窗课号可在入口追到

- **WHEN** 用户在排时间落点触发师生冲突弹窗并看到对端课号
- **THEN** 该课号与侧栏 / 按教师排 / 查询页中的已排锚点课号一致，且符合专业前缀规则

### Requirement: 不改排课交互与开课主数据范围

本能力 MUST NOT 修改排时间 / 排教室页面交互、右键菜单集合或时间教室独立性约定；MUST NOT 以本变更为由改写开课管理正式目录的真实课号策略（排课演示种子挂靠除外）。

#### Scenario: 排教室侧菜单不变

- **WHEN** 用户仅在排教室详情操作右键菜单
- **THEN** 菜单项与改前一致，仅若卡片展示课号则随种子新课号显示
