# Proposal

## Why

排课时间（按批次 / 教师 / 课程 / 联合排课）与排教室（按时间 / 场地类型）当前演示种子过大：联合排课 GE 每类 5 门、冲突与待排教室补齐课大量注入，列表与课表操作卡顿，客户演示反而难「走完全程」。需要把 Mock 收到可走通主路径的最小集，同时仍覆盖场地相关场景。

## What Changes

- 收束排课全局演示种子：**2–3 个入学批次**，每批次约 **5 门课**，每门课 **1–3 个课程组**；核心旅程教师总数约 **≤10**。
- 联合排课 GE：**G01–G04 每类 3 门**，每门 **1–2 组**（不再每类 5 门）。
- 保留「走完全程」所需样本：排时间（批次 / 教师 / 课程 / 联合含 GE）→ 排教室（按时间 / 按场地类型）→ 场地冲突或占用可演示；冲突类演示改为**薄覆盖**（少量锚点课），去掉为撑满列表的 weekday pad 等膨胀数据。
- 明确产品口径不变：GE 无固定上课批次，不出现在按批次排；可按教师、按课程、联合排。
- 不改变 `schedule-ephemeral-mock` 的「整页加载回种子」生命周期；只改种子体量与覆盖面。

## Capabilities

### New Capabilities

- `schedule-lean-demo-journey`: 排课管理演示种子的体量上限与全链路覆盖约定（时间侧入口 + 教室侧场地路径 + GE 联合排）。

### Modified Capabilities

- （无）`schedule-joint-ge-object` 的对象轴行为不变，仅演示数量下调，不改需求条文。

## Impact

- 主要改动：`app.js` 中 `ensureScheduleGlobalDemo` 相关种子（批次课、冲突样本、`getScheduleJointGeDemoSamples`、待排教室 / weekday pad、教师池与 `SCHEDULE_ROOM_*` 演示占用等）。
- 受影响页面：按入学批次排、按教师排、按课程排、联合排课、按时间排教室、按场地类型排、场地冲突查询。
- 遵守：排时间 / 排教室产品面独立性；查询条件布局标准。
- 可能影响依赖「大量演示课」的截图或口头话术；验收以「瘦身后仍能走完时间→教室→场地冲突」为准。
