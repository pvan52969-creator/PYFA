# Proposal

## Why

客户验收要求冲突演示**数据逻辑闭环**：弹窗里点名的冲突课，必须能在对应入口用真实已排数据追到，而不是「格子空着 / 列表看不见，却报学生冲突」。当前 lean 种子仍保留课表冲突查询专用课（如 `CQT102`）与跨批/不可见锚点；排时间侧学生冲突又扫全库同批，易出现「凭空冲突」。需要把冲突样本改成可走通的闭环剧本。

## What Changes

- 约定演示冲突的**闭环原则**：
  - **学生冲突**：冲突对方必须是**当前专业批次**内、已排好时间、且可在「按入学批次排」作用域中追到的课程（含已排完侧栏），不得靠「查询专用 / 不可见垫片」顶替。
  - **教师冲突**：冲突对方必须是**同一教师**已排好的课，且可在「按教师排」该教师课表中看到该节次。
  - **场地冲突 / 占用**：冲突对方或非排课占用必须真实占用该教室时段（已排教室或 `SCHEDULE_ROOM_NON_SCHEDULE_OCCUPANCY`），可在排教室路径复现。
- 调整 / 裁剪冲突演示种子：去掉或迁出破坏闭环的 `queryConflictDemo` 占位（或改为仅服务冲突查询页、且不参与排时间落点学生冲突同伴集——以闭环验收为准优先「同剧本可追」）。
- 保证每条保留的冲突口头路径都有：探测课 → 落点 → 弹窗课号 → 回入口可见已排锚点；与 `schedule-lean-demo-journey` 体量上限兼容。
- 不改冲突算法产品口径（同批学生互斥、教师全库、教室侧场地），只改**演示数据与可见性对齐**；不改排时间 / 排教室交互菜单独立性。

## Capabilities

### New Capabilities

- `schedule-closed-loop-conflict-demo`: 排课演示冲突（学生 / 教师 / 场地）的数据闭环与可追溯验收约定。

### Modified Capabilities

- （无）`schedule-lean-demo-journey` 仍为 change 内 delta、未进主 specs；本变更叠加闭环约束，不修改其体量条文。`schedule-joint-ge-object` 不变（GE 仍不参与学生冲突）。

## Impact

- 主要改动：`app.js` 冲突/查询演示样本、`ensureScheduleTimeConflictDemoCourses`、跨批占用、任务标记拷贝、必要时排时间可见性优先级（保证锚点进批次/教师侧栏）。
- 受影响：排时间落点冲突弹窗、按批次/教师课表着色、排教室场地冲突、课表冲突查询页（若迁出/改挂查询专用课）。
- 验收以客户口头路径为准：看见冲突课号 → 能在对应入口找到已排事实。
