## Context

See proposal.md — Why。

**已知条件（代码现状）：**

- 共同授课落在教学班 `sharedTeachingCode`；行内「共同授课」弹窗要求不同课号 + 至少一名相同任课教师，系统分配标记。
- 开课安排 Style2 已展示「共同授课状态 / 共同授课课号」，工具栏已有「一键复制」；分组页有「复制」历史安排。
- 特殊课程设置 store 现有：教室学时模式、Support 学院等；**无**共同授课预置字段。
- 移除共同教师后，现有逻辑**不会**自动清 `sharedTeachingCode`。
- 列表数据范围受角色约束：学院管理员通常仅本开课单位，教务处全校（与现有列表过滤一致）。

**已确认产品规则：**

1. 预置=**关联课号**（仅课号；开课时一课号可多安排，无法提前钉死教学班）。
2. 一键同步=**当前列表可见全集**，不依赖勾选；学院同步自然等于本单位数据，教务处等于全校可见数据。
3. 解绑：只解除**已无共同教师**的绑定；**纯手工且不在预置关联内**的绑定不同步解除。

## Goals / Non-Goals

**Goals:**

- 特殊课程设置可维护课号↔关联课号并持久化。
- 历史复制路径统一：不带入共同授课绑定。
- 工具栏「一键同步共同授课」：按关联课号 + 共同教师绑定；仅因无共同教师解绑；保护纯手工非预置绑定。
- 教师变更不即时解绑，同步为刷新入口。

**Non-Goals:**

- 改排课冲突引擎算法细节。
- 教师保存时自动触发同步。
- 通识/特殊开课全量同步 UI。
- 以勾选作为同步范围。

## Decisions

### 1. 预置存特殊课程设置，绑定仍写教学班

- **决策**：预置为课号级 `sharedTeachingPeerCodes`（关联课号列表）；运行时绑定仍用 `section.sharedTeachingCode`。
- **理由**：开课安排条数学期内才确定；课号关联可跨学期复用。
- **备选**：Y/N 无同伴表 —— 已否决（易误绑）。预绑具体 section —— 已否决（无法提前确认）。

### 2. 同步算法（已确认）

```
输入: 当前列表可见 sections S（无勾选过滤），特殊课程关联预置 P
1. 由 P 构建课号无向关联（A↔B）
2. 绑定：
   在 S 中找课号不同、课号彼此关联、且有共同教师的教学班连通分量
   每个 |C|≥2 的分量：分配/复用 sharedTeachingCode
3. 解绑（仅下列）：
   对 S 中已有 sharedTeachingCode 的组：
   - 若该组对应课号对属于预置关联（或组内至少一方在预置关联网络中且绑定可由同步管理）
     且组内已无共同教师 → 清除标记
   - 若为纯手工绑定且课号不在任何预置关联中 → 跳过，不清除
   - 不因「仅退出预置」且仍有共同教师而清除
4. 刷新列表；提示 bindCount / unbindCount
```

### 3. 「纯手工且不在预置」判定

- **决策**：绑定组内所有课号两两均不存在于特殊课程设置的关联关系中 → 视为纯手工非预置，同步不解绑。
- **备选**：增加 `sharedTeachingSource: manual|sync` 字段 —— 可后续增强；本版用预置关系推断，减少迁移。

### 4. 历史复制剥离共同授课

- **决策**：复制 apply 时显式 `sharedTeachingCode = ''`；不从源班拷贝。
- **覆盖**：一键复制确认路径；分组页复制确认路径。

### 5. UI

- 特殊课程设置：列表摘要列；编辑抽屉维护关联课号多选（不同课号；保存对称写回对端）。
- Style2 工具栏：`一键复制` 旁 `一键同步共同授课`；确认文案写明范围=当前列表可见数据、将绑定预置且有共同教师者、解除已无共同教师者、不改动手工非预置绑定。

## Risks / Trade-offs

- [多班同课号] → 按教学班 + 共同教师连通；同课号多班可能分到不同绑定组 → 规格允许。
- [无 source 字段] → 「纯手工非预置」靠推断，极端情况（曾预置绑定后删光关联）可能被当成手工保护 → 可接受；若需更严再加 source。
- [学院同步看不到外院同伴班] → 可能无法与外院班完成绑定/解绑 → 符合权限边界；教务处全校同步补齐。
- [演示数据] → 需补预置课号对。

## Migration Plan

- 旧数据无关联字段：视为未预置；同步不新建绑定；已有手工绑定保留。
- 回滚：隐藏同步按钮并忽略关联字段即可。
