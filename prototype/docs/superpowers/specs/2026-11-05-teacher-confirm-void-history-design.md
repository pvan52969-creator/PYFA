# 授课确认作废进 History + 安排详情确认提示

日期：2026-11-05  
状态：已实现（待联调点验）  
范围：教师端授课确认 Portal、开课分组「安排详情」、授课教师替换对确认包的副作用；顺带修复安排详情草稿行周次/学时类型控件溢出。

## 背景

当前安排指纹变化后，旧记录仍停在 Pending（按钮禁用 +「等重新下发」），无法确认、也不进 History。业务要求：

- 被改过的旧确认数据进 **History**，状态 **作废**
- 教师 **A 被换成 B** 时，A 的该课确认保留在 History 并标作废，邮件告知 A 已 cancel
- 改安排前在「安排详情」操作/保存时二次确认提示
- 新 Pending **仅**在教务重新下发后出现（方案 A）

## 目标

1. 确认状态增加 `cancelled`（界面文案：**作废**；对外/邮件可称 cancel）
2. History 展示：已确认 / 代确认 / 退回 / **作废**
3. Pending 仅可操作的 `pending`（快照与当前安排一致）
4. 安排变更、教师替换按规则作废旧确认；不作废「仅撤回生效」路径
5. 安排详情在进入编辑类操作与行内 ✓ 保存时提示作废后果
6. 修复安排详情草稿行周次、学时类型控件溢出

## 非目标

- 正式邮件 HTML 模板定稿（原型可用 toast / 历史日志占位；模板待业务提供）
- 一进分组页就常驻提示
- 重做 Syllabus（已有入口则保留）
- 改排时间 / 排教室详情交互

## 状态模型

按「教师 × 学期 × 课程班」的确认段状态：

| status | 教师端 Tab | 可否点确认 | 说明 |
|---|---|---|---|
| `pending` | Pending | 仅当快照与当前安排指纹一致 | 已下发待确认 |
| `confirmed` / `admin-proxy` | History | 否 | 已确认 / 代确认 |
| `disagreed` | History | 否 | 退回 |
| `cancelled` | History | 否 | **作废**（安排变更或被替换） |
| `draft` | 不进 Portal 可操作列表 | 否 | 未下发 |

包级 `pkg.status` 重算时：存在可操作 `pending` → pending；否则按现有优先级综合 History 态（含 cancelled）。

## 作废触发

### A. 安排内容变更（指纹变化）

- **时机**：安排详情行内 ✓ 保存成功，且该保存导致某教师在该课的安排指纹相对其已下发/已确认快照变化。
- **动作**：将该教师该课状态改为 `cancelled`；写入 history（type: `cancelled` / reason: `arrangement-changed`）；**不**自动新建 `pending`。
- **Pending**：该课从 Pending 消失；须教务重新下发后才再出现。
- **范围**：仅指纹变化的教师；未变教师保持原状。

### B. 授课教师替换（A 被换成 B）

- **动作**：被换下的 **A** 在该课的确认段 → `cancelled`（reason: `teacher-replaced`），保留快照进 History；触发「已 cancel」通知（原型占位）。
- **B**：不继承 A 的确认；需教务对新安排下发后，B 才进 Pending。
- **生效状态**：按现有替换规则，安排可仍为已生效。

### C. 不作废

- 任务安排「撤回」仅打回生效态，**不**将授课确认作废（与现行「撤回后确认保留」一致）。
- 共同授课/Coordinator 等展示字段变化（已不在指纹内）不触发作废。

## 安排详情提醒

**前提**：本课存在任一教师该课确认段为 `pending` / `confirmed` / `admin-proxy`（已下发或已确认）。

**时机（两次，文案可共用）**：

1. 点击：行操作 ✎ / ⧉，或安排详情头「新增 / 删除 / 配置共同授课」——**进入操作前**确认，取消则中止。
2. 点击行内 ✓（`saveOfferingGroupStatusAssignDraft`）——**保存前**再确认，取消则不保存。

**文案（可微调）**：

> 本课已下发或已完成授课确认。继续操作将作废相关教师的原确认记录（进入 History，状态为「作废」）；须由教务重新下发后，教师方可再次确认。

同一编辑会话内：点 ✎ 已确认过，保存时仍再确认一次（产品已定）。

## 教师端 Portal

- Pending：仅 `pending` 且快照一致 → 可确认；不再用「脏 pending 灰按钮」作为主路径。
- History：含 `cancelled`，Status 展示「作废」。
- 去掉（或降级）「安排已变更，请等待教务重新下发」作为 Pending 卡死态的主提示；作废后用户应在 History 看到作废记录。

## 验收要点

1. G0103 类场景：改学分/学时保存后，原 pending → History「作废」；Pending 空；重新下发后出现新 pending 可确认。
2. A→B 替换：A History「作废」+ 占位通知；B 无自动已确认。
3. 仅撤回生效：确认不作废。
4. 安排详情：有确认数据时，点 ✎ 与点 ✓ 各弹一次；取消不改数据。
5. 草稿行周次/学时类型不再横向溢出。
