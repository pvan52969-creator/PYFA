## Goals / Non-Goals

**Goals:**

- 最小改动：只在已有 filter DOM 上增控件 + 在既有 filter 函数里加条件。
- 交互与现页一致（查询/重置按钮文案、回车触发若已有则保留）。
- 选项数据复用现有 helper（学院/专业/批次、教职工类型枚举、学期下拉）。

**Non-Goals:**

- 不做跨页统一 Filter SDK / 后端查询 API。
- 不为无筛选栏的页新建筛选栏。
- 不改列表列结构、排序、导出字段（除非筛选项依赖列数据已有）。
- 不恢复已注释隐藏的 nav（学期安排导出等）。

## Decisions

### 1. 按页增量，不抽大一统组件

- **选择**：每页在现有 `filter-bar` / `schedule-query-fields` 内加 `label+input/select`，过滤逻辑写进该页已有 `filter*Rows` / `render*`。
- **理由**：各页状态与级联已分叉；强行抽象收益低、回归面大。
- **备选**：共用 `buildScheduleListFilterHtml(fields)` — 留作后续，本期不做。

### 2. 模糊匹配口径

- 课号 / 课程班名称 / 教师：`includes` 大小写不敏感，匹配行上已展示字段（及 `code`/`name`/`teacherId`/`teachers` 同源字段）。
- 下拉：精确匹配「全部」= 不筛。

### 3. 学期控件

- 入口列表若学期只读（跟随当前排课学期）：新增筛选项不改学期模型，只加关键词类。
- 冲突/调课等已有学期 select：保持；新页若缺且列表跨学期则补 select。

### 4. 教室入口补课号/教师

- 列表行聚合维度是 Day 或场地类型时，过滤条件作用在「该桶下是否含匹配课程/教师的任务」：桶内无匹配则隐藏整行（与状态过滤同一层）。

### 5. 调课列表英文/中文混排

- Class Adjustment / Approval 保持现有英文字段标签；新补字段优先与表头语言一致（该页英则英）。

### 6. 实现顺序（降低返工）

1. 三大排课入口（批次/教师/课程）  
2. 两大排教室入口  
3. 场地冲突补学院批次  
4. 自动排课/教室状态  
5. 调课管理各列表缺口扫尾  

## Risks / Trade-offs

- **[Risk] 聚合行过滤语义不清（按 Day 桶）** → Mitigation：设计约定「桶内任一课程/教师命中即保留」；在 tasks 验收写明。
- **[Risk] 筛选项过多换行拥挤** → Mitigation：沿用现有 filter-bar 换行；必要时 `styles` 微调 gap，不加折叠面板（非目标）。
- **[Risk] 演示数据缺字段导致筛永远空** → Mitigation：过滤对缺失字段视为不匹配该条件；重置可回全部。
- **Trade-off**：不做统一组件 → 短期重复 DOM/逻辑，长期可再收。

## Migration Plan

- 纯前端原型：改完刷新即可；无数据迁移。
- 回滚：还原各页 filter DOM 与对应 `app.js` 过滤分支。

## Open Questions

- 课表密度查询是否在后续单独加筛选栏：本期按「无栏则不加」处理；若产品要加，另开变更。
- 「是否启用」用于教室开放时间：若列表无显式启用列，可改为不补该项（实现时以列是否存在为准）。
